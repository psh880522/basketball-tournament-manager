## 1. 리서치 반영 요약

### 기존 UI 패턴에서 재사용할 것

| 항목 | 파일 | 재사용 방식 |
|---|---|---|
| `Card` | `components/ui/Card.tsx` | 디비전 카드, 신청 요약 카드, 상태 카드 컨테이너 |
| `Badge` | `components/ui/Badge.tsx` | 대회 상태, 신청 상태, 디비전 뱃지 |
| `Button` | `components/ui/Button.tsx` | CTA (primary), 보조 액션 (secondary), 텍스트 버튼 (ghost) |
| `BottomSheet` | `components/ui/BottomSheet.tsx` | 모바일 디비전 선택 바텀시트 (이미 구현됨) |
| `Input` | `components/ui/Input.tsx` | 입금자명 입력 폼 |
| `RosterPicker` | `components/team/RosterPicker.tsx` | 신청 폼 로스터 선택 |
| 2단 grid 레이아웃 | `app/(app)/tournament/[id]/page.tsx` | `md:grid-cols-3` 구조 유지 (이미 구현됨) |
| sticky 사이드바 패턴 | `app/(app)/tournament/[id]/page.tsx` | `style={{ top: "calc(var(--header-height)..." }}` 유지 |
| 병렬 데이터 로드 | 전체 서버 컴포넌트 | `Promise.all([...])` 패턴 |
| `force-dynamic` | apply, my-applications | 캐시 없는 실시간 렌더링 |

### 새로 설계할 것

- **디비전 선택 인터랙션** — 대회 상세 우측 sticky 패널의 디비전 카드를 클릭 가능하게 변환. 현재는 읽기 전용.
- **모바일 하단 고정 바** — 모바일에서 선택된 디비전명 + "신청하기" 버튼을 화면 하단에 고정.
- **디비전 선택 바텀시트** — 모바일에서 "신청하기" 탭 시 슬라이드업. 기존 `BottomSheet` 컴포넌트 활용.
- **디비전 요약 카드** — 신청 페이지 상단에 URL 파라미터로 받은 디비전 정보를 읽기 전용으로 표시.
- **로스터 인원 카운터** — 신청 폼에서 선택된 인원 수 + 최소 인원 가이드 실시간 표시.
- **신청 완료 배너** — `my-applications/[applicationId]?from=apply` 진입 시 상단에 완료 축하 + 입금 안내 배너.

### 기존 패턴에서 의도적으로 변경할 것

| 변경 사항 | 이유 |
|---|---|
| 대회 상세 디비전 카드: 읽기 전용 → 선택형 | 디비전을 상세 페이지에서 골라야 apply 페이지가 단순해짐. 현재는 /apply에서 다시 드롭다운으로 선택해야 해서 UX 중복 발생. |
| apply 폼의 division 드롭다운 제거 | URL 파라미터로 받아 디비전 요약 카드로 대체. 결정 단계를 상세 페이지로 이동. |
| CTA 링크: `/apply` → `/apply?division=xxx` | 선택된 디비전 ID를 URL에 포함해 신청 페이지에서 재선택 불필요. |
| 신청 완료 후 리다이렉트: 단순 push → `?from=apply` 포함 | 완료 직후 입금 안내를 상단에 강조 표시하기 위한 분기 신호. |

## 4. 화면별 상세 설계

### 4-1. 대회 상세 (`/tournament/[id]`)

#### 목적
대회 정보를 충분히 읽은 뒤 디비전을 선택하고 신청을 시작하는 진입 화면. 쇼핑몰 상품 상세 페이지와 동일한 역할.

#### 현재 구조 (코드 기준)
`tournament/[id]/page.tsx`는 이미 `md:grid-cols-3` 2단 레이아웃과 sticky 우측 패널을 구현하고 있다.

**현재 콘텐츠 배치**:
- 포스터: 상단 전체 너비 Hero 영역 (grid 밖)
- 좌측(2/3): 디비전 카드 목록 + 대회 소개
- 우측(1/3) sticky: CTA 버튼 + 신청 상태

**목표 콘텐츠 배치 (변경)**:
- 포스터: Hero 제거 → 좌측 컬럼 상단으로 이동
- 좌측(스크롤): 포스터 이미지 + 대회 소개/규칙
- 우측(sticky): 대회명/날짜/장소/상태뱃지 + 디비전 카드(선택형) + CTA

**변경이 필요한 이유**: 사용자가 포스터와 설명을 스크롤하며 읽는 동안 오른쪽에서 모든 결정(대회 파악 → 디비전 선택 → 신청)이 완결된다. 현재 구조는 디비전이 왼쪽에 있어 스크롤 중 신청 버튼이 시야에서 벗어나는 문제가 있다.

**현재 추가 누락된 것**:
1. 디비전 카드가 클릭 불가(읽기 전용) — 선택 인터랙션 없음
2. CTA가 `/apply`로 이동 — 디비전 ID 미포함
3. 모바일에서 CTA가 스크롤에 묻혀 접근성 낮음 (하단 고정 바 없음)

#### 목표 레이아웃 구조

```
┌─────────────────────────┬──────────────────────────┐  (md 이상)
│  왼쪽 (스크롤됨)         │  오른쪽 (sticky 고정)     │
│                         │                          │
│  포스터 이미지           │  [모집중] 뱃지             │
│  (비율 유지, rounded)   │  대회명                   │
│                         │  날짜 · 장소              │
│  ──────────────────     │  ──────────────────────   │
│  대회 소개               │  ○ 일반부  50,000원       │
│  규칙 / 운영 방식        │  ● 오픈부  30,000원 ←선택 │
│  (없으면 영역 없음)      │    정원: 8/16팀           │
│                         │  ──────────────────────   │
│                         │  [팀 참가 신청 →]         │
│                         │  (미선택 시 비활성)       │
└─────────────────────────┴──────────────────────────┘

─────────── 모바일 하단 고정 ─────────────
│  [오픈부 선택됨]           [신청하기 →]  │  (md 미만)
──────────────────────────────────────────

(모바일 스크롤 순서: 포스터 → 대회명/날짜/장소 → 디비전 카드 → 대회 소개)
```

#### 컴포넌트 목록

| 컴포넌트 | 신규/기존 | 역할 |
|---|---|---|
| `TournamentDetail` (Server) | 기존 — 수정 | 데이터 페치, 좌측 정적 영역 렌더링, `TournamentStickyPanel`에 데이터 전달 |
| `TournamentStickyPanel` (Client) | **신규** | 우측 sticky 패널 전체 — 대회 기본정보 + 디비전 선택 카드 + CTA 버튼 |
| `MobileApplyBar` (Client) | **신규** | 모바일 하단 고정 바 — 선택된 디비전명 + 신청 버튼 |
| `DivisionBottomSheet` (Client) | **신규** | 모바일 바텀시트 — 기존 `BottomSheet` 래핑 |

> `page.tsx`는 Server Component를 유지한다. 좌측(포스터 + 설명)은 정적이므로 Server 렌더링. 우측은 디비전 선택 상태가 필요하므로 `TournamentStickyPanel` Client Component로 분리. 모바일 하단 바(`MobileApplyBar`)는 `TournamentStickyPanel` 내부에서 함께 관리한다.

**DivisionStickyPanel → TournamentStickyPanel 이름 변경 이유**: 이 컴포넌트가 디비전만이 아니라 대회명/날짜/장소/상태뱃지까지 우측 패널 전체를 담당하므로 명칭을 더 넓게 변경.

#### 인터랙션

**디비전 선택 (데스크탑)**
```
디비전 카드 클릭
  → selectedDivisionId 상태 업데이트
  → 클릭한 카드: border-[#FF6B00] bg-[#FFF5EC] ring-1 적용
  → 이전 선택 카드: 원래 스타일 복원
  → 우측 sticky 패널:
      - 선택된 디비전 이름/참가비 요약 표시
      - "팀 참가 신청" 버튼 활성화 (Link href → /apply?division=xxx)
```

**디비전 선택 (모바일)**
```
하단 고정 바의 "신청하기" 버튼 탭
  → 디비전 1개: 바텀시트 없이 /apply?division=xxx로 바로 이동
  → 디비전 2개+: DivisionBottomSheet 열림
      → 카드 탭 → 선택 하이라이트 + "이 부문으로 신청하기" CTA 활성화
      → CTA 탭 → /apply?division=xxx로 이동, 바텀시트 닫힘
```

**이미 신청된 경우**
```
teamApplication 존재
  → 우측 패널: "팀 참가 신청" 버튼 숨김
  → "신청 현황 보기" / "다시 신청하기" 버튼 표시 (기존 로직 유지)
  → 내가 신청한 디비전 카드: border-amber-300 bg-amber-50 "내 신청" 뱃지 (기존 유지)
  → 모바일 하단 바: "신청 현황 보기 →" 버튼으로 변경
```

#### 엣지 케이스

| 케이스 | 처리 |
|---|---|
| 디비전 0개 | 우측 sticky 패널 내 "부문 정보가 없습니다." 텍스트 표시 |
| 디비전 1개 | 진입 시 자동 선택, 우측 패널 CTA 즉시 활성화 |
| 정원 마감(isFull) | 카드 `opacity-60`, "마감" 뱃지, 클릭 비활성 (`pointer-events-none`) |
| tournament.status ≠ 'open' | CTA 버튼 미노출, 결과 배너 표시 (기존 로직 유지) |
| description 없음 | 대회 소개 카드 미렌더링 (기존 `tournament.description &&` 조건 유지) |
| 비인증 사용자 | CTA href="/login", 선택 인터랙션은 허용 (읽기는 전체 공개) |

#### 모바일 대응

- `md:grid-cols-3` 구조는 그대로 — 모바일에서는 단일 컬럼으로 자연스럽게 쌓임
- 우측 sticky 패널은 모바일에서 일반 흐름 카드로 렌더링 (기존 동작)
- **추가**: `MobileApplyBar` — `fixed bottom-0 inset-x-0 z-30 bg-white border-t border-slate-200`, `md:hidden`으로 데스크탑에서 숨김
- MobileApplyBar 높이(약 64px)만큼 main 하단에 `pb-16 md:pb-0` 패딩 추가

### 4-2. 신청 페이지 (`/tournament/[id]/apply?division=xxx`)

#### 목적
선택한 디비전으로 팀을 고르고 초기 로스터를 제출하는 실행 화면. 결정은 이미 상세 페이지에서 완료되었으므로 빠른 실행에 집중.

#### 레이아웃 구조

```
[뒤로가기 링크 → /tournament/[id]]
[대회명]  참가 신청

┌──────────────────────────────────────┐
│  선택된 디비전 요약 카드 (읽기 전용)  │  ← URL ?division=xxx 기반
│  일반부 · 참가비 50,000원 · 정원 16팀 │
│  변경하려면 [← 대회 상세로]          │
└──────────────────────────────────────┘

┌──────────────────────────────────────┐
│  팀 선택                              │
│  [드롭다운 — captain인 팀만]          │
└──────────────────────────────────────┘

┌──────────────────────────────────────┐
│  로스터 선택                          │
│  3명 선택됨 / 최소 5명 이상 필요     │  ← 인원 카운터
│  [RosterPicker]                       │
└──────────────────────────────────────┘

[신청하기]  ← 최소 인원 미달 시 비활성 + 툴팁
```

#### 컴포넌트 목록

| 컴포넌트 | 신규/기존 | 역할 |
|---|---|---|
| `TournamentApplyPage` (Server) | 기존 — 수정 | searchParams에서 divisionId 추출, 없으면 /tournament/[id]로 redirect |
| `ApplyTeamForm` (Client) | 기존 — 수정 | division 드롭다운 제거, divisionId를 prop으로 수신 |
| `DivisionSummaryCard` | **신규** | 선택된 디비전 요약 읽기 전용 카드 |
| `RosterCounter` | **신규** | "N명 선택됨 / 최소 M명 이상" 카운터 텍스트 |
| `RosterPicker` | 기존 — 재사용 | 선수 다중 선택 UI |

#### 인터랙션

**divisionId 수신**
```
page.tsx (Server):
  searchParams.division → divisionId
  divisionId 없음 → redirect(`/tournament/[tournamentId}`)
  getDivisionsByTournament()로 해당 division 정보 조회
  DivisionSummaryCard에 props로 전달
```

**로스터 최소 인원 검증**
```
selectedMemberIds 길이 변화 → RosterCounter 텍스트 업데이트
  - 부족: "3명 선택됨 / 최소 5명 이상 필요" (텍스트: text-amber-600)
  - 충족: "5명 선택됨 ✓" (텍스트: text-emerald-600)

신청하기 버튼:
  - teamId 미선택 OR 인원 < division.min_roster_size → disabled

min_roster_size 출처:
  - DB: divisions.min_roster_size (NOT NULL DEFAULT 5) — 0251 마이그레이션 선행 필요
  - 서버 검증: applyWithRosterAction에서 division.min_roster_size 조회 후 memberIds.length와 비교
  - 클라이언트는 UX 안내용이고, 실제 강제는 서버 액션에서 수행
```

**신청 완료**

### 4-3. 신청 상세 / 완료 (`/my-applications/[applicationId]`)

#### 목적
신청 완료 직후 입금 안내를 즉시 확인하고, 이후 상태 변화(승인, 대기, 만료)를 추적하며 로스터를 관리하는 화면.

#### 현재 구현 상태 (코드 기준)
`ApplicationStatusSection.tsx`에 이미 구현된 것:
- 6가지 상태별 UI (payment_pending / paid_pending_approval / confirmed / waitlisted / expired / cancelled)
- `PaymentForm` — 입금자명/메모 입력 + "입금 완료 신고" 버튼
- `CancelButton` — 2단계 확인(취소 확인 → 실행)
- `waitlist_position` 대기 순번 표시
- `payment_due_at` 정적 날짜 문자열 표시

**추가 필요한 것**:
1. 신청 완료 직후(`?from=apply`) 상단 완료 배너
2. `payment_due_at` 실시간 카운트다운 (현재는 정적 날짜 텍스트만)

#### 레이아웃 구조

#### 컴포넌트 목록

| 컴포넌트 | 신규/기존 | 역할 |
|---|---|---|
| `MyApplicationDetailPage` (Server) | 기존 — 수정 | searchParams에서 `from` 파라미터 추출 후 하위 컴포넌트에 전달 |
| `CompletionBanner` (Client) | **신규** | `?from=apply` 시 표시되는 완료 배너. 입금 안내 섹션으로 스크롤 이동 버튼 포함 |
| `ApplicationStatusSection` (Client) | 기존 — 수정 | `PaymentDueCountdown` 서브 컴포넌트 추가 |
| `PaymentDueCountdown` (Client) | **신규** | `payment_due_at`까지 남은 시간을 `useEffect` + `setInterval`로 실시간 표시 |
| `RosterSection` (Client) | 기존 — 유지 | 로스터 편집 UI |

#### 인터랙션

**CompletionBanner — "입금 안내 바로 보기" 클릭**
```
document.getElementById('payment-section').scrollIntoView({ behavior: 'smooth' })
```

**PaymentDueCountdown**
```
props: dueAt: string | null

useEffect(() => {
  const interval = setInterval(() => {
    const diff = new Date(dueAt) - new Date()
    // HH시간 MM분 SS초 형식으로 표시
    // diff < 0 → "기한이 만료되었습니다"
  }, 1000)
  return () => clearInterval(interval)
}, [dueAt])
```

표시 형식:
- 24시간 이상: "입금 기한까지 1일 3시간 남음"
- 24시간 미만: "입금 기한까지 03:42:15 남음" (HH:MM:SS 빨간색)
- 만료: "입금 기한이 지났습니다" (회색, 만료 처리는 Edge Function이 담당)

#### 엣지 케이스

| 케이스 | 처리 |
|---|---|
| `from=apply` 없음 | CompletionBanner 미표시 (일반 접근) |
| `final_amount === 0` | PaymentForm 미표시, "운영자 확인 후 확정" 안내 (기존 유지) |
| `payment_due_at null` | 카운트다운 미표시 |
| 로스터 잠금(start_date <= today) | RosterSection 읽기 전용 (기존 유지) |
| captain이 아닌 팀원 | RosterSection 읽기 전용, PaymentForm/CancelButton 미노출 (기존 유지) |
| 비활성 상태(cancelled/expired) | 로스터 섹션 미표시 (기존 `isActive` 조건 유지) |

#### 모바일 대응

- 단일 컬럼 (`max-w-2xl`) — 기존과 동일
- CompletionBanner는 화면 상단에 전체 너비로 표시 (`variant="highlight"` Card)
- PaymentDueCountdown은 `payment_pending` 폼 상단에 인라인으로 표시

## 8. 구현 시 주의사항

### 8-1. page.tsx Server Component 유지

`tournament/[id]/page.tsx`는 Server Component를 유지해야 한다. 우측 sticky 패널 전체를 `TournamentStickyPanel` (Client Component)로 분리하고, 좌측(포스터 + 소개)은 page.tsx에서 직접 Server 렌더링한다. page.tsx에서 Server 데이터 페치를 완료한 뒤 `TournamentStickyPanel`에 `tournament`, `divisions`, `myApplication` 등을 props로 내려주는 구조.

### 8-2. TournamentStickyPanel이 우측 sticky 영역 전체 담당

현재 page.tsx에서 우측 sticky 패널 안의 CTA 버튼이 `teamApplication`, `tournament.status` 등 조건에 따라 분기된다. `TournamentStickyPanel`이 대회 기본정보(대회명, 날짜, 장소, 상태뱃지)부터 디비전 카드, CTA 버튼까지 전부 담당한다. 기존 버튼 분기 로직(canReapply, isResultVisible 등)을 빠뜨리지 않도록 주의.

### 8-3. 모바일 하단 바와 기존 네비게이션 z-index 충돌 확인

`MobileApplyBar`는 `z-30`. 기존 헤더 또는 네비게이션 바의 z-index와 충돌 여부 확인 필요. 현재 `BottomSheet`가 `z-40`(오버레이) / `z-50`(시트)를 사용하므로 MobileApplyBar는 `z-30`으로 그 아래에 위치.

### 8-4. 디비전 1개 자동선택 시 MobileApplyBar 초기 상태

`divisions.length === 1`이면 `TournamentStickyPanel` 초기 상태에서 `selectedId = divisions[0].id`로 자동 설정. MobileApplyBar도 진입 시 즉시 선택된 디비전을 표시하고 버튼 활성화되어야 함.

### 8-5. apply 페이지 뒤로가기

`DivisionSummaryCard`의 "변경하려면 대회 상세로" 링크는 `/tournament/[tournamentId]`로 단순 Link. `router.back()`은 사용하지 않는다 — 직접 URL 입력으로 접근했을 때 back이 동작하지 않을 수 있기 때문.

### 8-6. PaymentDueCountdown과 서버 시간 차이

클라이언트 `new Date()`는 사용자 로컬 시간 기준. 서버 저장 `payment_due_at`은 UTC. 브라우저가 자동으로 UTC로 파싱하므로 `new Date(dueAt)`는 정상 동작하나, 사용자 타임존이 KST가 아닐 경우 표시 시간이 혼동될 수 있음. 서비스 대상이 국내 한정이면 무시 가능.

### 8-7. CompletionBanner의 스크롤 앵커

`ApplicationStatusSection`에 `id="payment-section"` 추가 필요. CompletionBanner의 스크롤 버튼은 `document.getElementById('payment-section')?.scrollIntoView()`로 처리.

### 8-8. 반응형 처리 우선순위

1. 모바일 MobileApplyBar — 신청 CTA 접근성에 직결, 최우선
2. TournamentStickyPanel 카드 선택 하이라이트 — 데스크탑에서만 동작하면 됨
3. DivisionBottomSheet — 모바일 전용, 기존 BottomSheet 래핑이라 구현 비용 낮음

### 8-9. 본인인증 체크 — server-side 강제 필수

`apply/page.tsx`에서 `getUserWithRole()`은 `identity_verified_at`을 반환하지 않으므로 `profiles` 테이블을 별도 조회해야 한다. 클라이언트에서만 체크하면 우회 가능하므로 반드시 Server Component(`apply/page.tsx`)에서 redirect로 강제.

```typescript
// apply/page.tsx Server Component
const profile = await getProfile(userId)  // profiles 직접 조회
if (!profile.identity_verified_at) {
  redirect(`/onboarding/identity-verification?redirectTo=...`)
}
```

### 8-10. 최소 로스터 강제 시점 — 클라이언트 안내 + 서버 이중 검증

- **클라이언트**: `selectedMemberIds.length < division.min_roster_size`이면 CTA 비활성 + RosterCounter 경고 색상 → UX 안내용
- **서버**: `applyWithRosterAction`에서 division 재조회 후 `min_roster_size`와 비교 → 실제 강제 (클라이언트 우회 방어)
- **DB default**: `min_roster_size NOT NULL DEFAULT 5` — 0251 마이그레이션 후 기존 디비전도 자동으로 5 적용

## 9. 결론 및 플랜 단계 전달 메모

### 이번 UI 설계의 핵심 변경점 요약

1. **대회 상세 → 레이아웃 재구성 + 디비전 선택**: 포스터·소개를 좌측에, 대회기본정보·선택형 디비전 카드·CTA를 우측 sticky에 배치. 우측 전체를 `TournamentStickyPanel` (Client Component)로 교체. page.tsx는 Server Component 유지.

2. **신청 페이지 단순화**: URL `?division=xxx`로 디비전을 받아 드롭다운 제거. 팀 선택 + 로스터 제출에만 집중.

3. **모바일 UX**: `MobileApplyBar` + `DivisionBottomSheet`로 모바일에서 스크롤 없이 신청 가능. 기존 `BottomSheet` 컴포넌트 재활용으로 구현 비용 낮음.

4. **참가 자격 체크 추가**: `apply/page.tsx`에 `identity_verified_at` 서버 체크 추가. 컬럼은 이미 존재, 체크 로직만 없었음.

5. **최소 로스터 강제**: `divisions.min_roster_size` DB 컬럼 추가 + 서버 액션 검증 + 클라이언트 UI 안내. 클라이언트는 UX용, 서버가 실제 강제.

6. **신청 완료 배너**: `?from=apply` 파라미터로 직후 진입을 감지해 입금 안내를 상단에 강조. 이후 재방문에서는 일반 상태 화면.

7. **입금 기한 카운트다운**: `PaymentDueCountdown`으로 실시간 표시. 만료 처리는 DB/Edge Function 담당이고 UI는 표시만.

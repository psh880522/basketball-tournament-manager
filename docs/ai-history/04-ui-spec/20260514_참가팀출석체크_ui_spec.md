# 참가팀 출석 체크 UI 설계

---

## 1. 리서치 반영 요약

### 기존 UI 패턴에서 재사용할 것

| 항목 | 파일 / 패턴 |
|------|------------|
| 페이지 외부 래퍼 | `min-h-screen bg-gray-50 px-4 py-8` |
| 컨텐츠 래퍼 | `mx-auto max-w-4xl space-y-6` |
| 뒤로 가기 링크 | `text-sm text-gray-500` (← 대회 대시보드) |
| `Card` 컴포넌트 | 섹션 구분 및 KPI 카드 |
| `Badge` 컴포넌트 | 출석 상태 표시 |
| `Button` 컴포넌트 | 액션 버튼 |
| `Table` compound 컴포넌트 | 팀 목록 테이블 |
| 체크박스 스타일 | `h-4 w-4 rounded border-slate-300 text-amber-500 focus:ring-amber-400` |
| `useTransition` + Server Action | 체크박스 토글 시 optimistic update |
| `EmptyState` 컴포넌트 | 확정 팀 없는 경우 |

### 새로 설계할 것

- 출석 체크 페이지 전체 (`/admin/tournaments/[id]/attendance`)
- 출석 요약 KPI 카드 (전체/출석/미확인 팀 수)
- Excel 다운로드 버튼 (API route 연동)
- ProgressIndicator에 "출석 체크" 스텝 카드

### 기존 패턴에서 의도적으로 변경할 것

| 변경 내용 | 이유 |
|-----------|------|
| 체크박스를 `<form>` 대신 `onChange` 이벤트 + server action으로 처리 | 행 단위 즉시 반영이 필요. redirect 없이 inline feedback 제공 |
| 테이블 헤더에 "전체 선택" 체크박스 미제공 | 대회 당일 현장 체크 용도라 개별 확인이 원칙, 일괄 체크는 출결 오류 유발 가능 |
| 디비전/조 기준으로 테이블 그룹핑 없이 평탄 나열 | 조 수가 많아질 수 있고 단순 스크롤이 현장 운영에 더 빠름. 향후 그룹핑 추가 가능 |

## 2. 기존 UI 패턴 분석

### 2-1. 사용 중인 UI 라이브러리 및 컴포넌트

## 4. 화면별 상세 설계

### 4-1. 대회 운영 대시보드 (수정)

**목적**: 기존 5단계 플로우에 "출석 체크" 단계를 삽입해 운영자가 단계별 진행 상태를 파악할 수 있게 한다.

**레이아웃 구조**
- 변경 없음. ProgressIndicator의 스텝 배열에 index 3 위치에 새 스텝 카드를 추가
- 기존 `sm:grid-cols-2 lg:grid-cols-3` 그리드는 6개 카드에서도 2행 3열로 자연스럽게 맞아떨어짐

**스텝 카드 설계 (출석 체크)**
```
┌──────────────────────────────────┐
│ ● 출석 체크          [진행중]    │
│                                  │
│ 경기 시작 전 팀 현장 출석을      │
│ 확인합니다.                      │
│                                  │
│ [출석 체크]  [결과 입력]         │
└──────────────────────────────────┘
```

**스텝 상태 조건**

| 상태 | 조건 |
|------|------|
| `pending` | 스케줄 미완료 (`scheduledMatches < totalMatches`) |
| `active` | 스케줄 완료 (`scheduledMatches === totalMatches && totalMatches > 0`) |
| `done` | 없음 (출석 체크는 완료 조건 없음 — 항상 active 또는 pending) |

**액션 버튼**
- `[출석 체크]` (primary) → `/admin/tournaments/[id]/attendance`  
  — enabled 조건: `!isFinished && scheduledMatches === totalMatches && totalMatches > 0`  
  — disabled reason: isFinished → "종료된 대회", 스케줄 미완료 → "먼저 스케줄을 완료하세요"
- `[결과 입력]` (secondary) → `/admin/tournaments/[id]/result`  
  — enabled 조건: `!isFinished && totalMatches > 0`
  
[REMOVE] 결과 입력 버튼 제거

**TournamentProgressState 변경**
- `resolveState()` 수정: SCHEDULE 완료 시 `ATTENDANCE_CHECK` 반환 (기존 `RESULT` 직행 대신)
- `resolveNextAction()` 분기 추가: state === "ATTENDANCE_CHECK" → 출석 체크 페이지로 이동

### 4-2. 참가팀 출석 체크 페이지 (신규)

**목적**: 운영자가 대회 당일 경기 시작 전, 확정 팀의 현장 출석 여부를 체크하고 Excel로 내보낸다.

**사용자 시나리오**
1. 운영자가 대시보드 "출석 체크" 버튼 클릭 → 페이지 진입
2. 디비전/조/팀명/주장/연락처 목록 확인
3. 도착한 팀의 체크박스 클릭 → 즉시 저장 (optimistic update)
4. 출석 요약 KPI 확인 (전체/출석/미확인)
5. 필요 시 Excel 다운로드
6. 체크 완료 후 "결과 입력으로 이동" 클릭

**레이아웃 구조 (전체 화면)**

```
min-h-screen bg-gray-50 px-4 py-8
└── mx-auto max-w-4xl space-y-6
    ├── [← 대회 대시보드]
    ├── <h1> 참가팀 출석 체크
    │
    ├── [KPI 요약 카드 섹션]               ← Card default
    │   └── grid sm:grid-cols-3
    │       ├── 전체 팀: N팀
    │       ├── 출석 확인: N팀
    │       └── 미확인: N팀
    │
    ├── [헤더 액션 줄]
    │   ├── <h2> 팀 목록 (text-lg font-semibold)
    │   └── [Excel 내보내기 ↓] (secondary Button, 오른쪽 정렬)
    │
    ├── [AttendanceTable 컴포넌트]         ← 클라이언트
    │   └── Table 컴포넌트 사용
    │       ├── thead: 디비전 | 조 | 팀명 | 주장이름 | 연락처 | 출석
    │       └── tbody: 팀 행 × N
    │           └── 각 행: 텍스트 셀 × 5 + 체크박스 셀 × 1
    │
    └── [결과 입력으로 이동 →] (secondary Button, 오른쪽 정렬)
```

**KPI 카드 상세**

```
┌─────────────────────────────────────────────────────────┐
│  [전체 팀]          [출석 확인]         [미확인]         │
│  12팀               8팀                 4팀              │
│  참가 확정          출석 체크됨          체크 안됨         │
└─────────────────────────────────────────────────────────┘
```

- variant: `muted` (배경 `bg-[#f0f0f0]`)
- 숫자: `text-lg font-semibold text-gray-900`
- 레이블: `text-xs text-gray-500`
- 서브텍스트: `text-xs text-gray-400`
- "미확인" 카드: 미확인 > 0이면 `text-rose-600`으로 강조

**테이블 상세 설계**

헤더:
```
| 디비전  | 조     | 팀명   | 주장이름 | 연락처        | 출석  |
| 6rem    | 5rem  | 1fr    | 7rem    | 9rem          | 4rem  |
```

행 예시:
```
| A 디비전 | A조  | 한빛 FC | 김철수  | 010-1234-5678  | [☑] |
| A 디비전 | B조  | 드래곤  | -       | 010-9876-5432  | [☐] |
| B 디비전 | -    | 썬더스  | 박민수  | 010-1111-2222  | [☐] |
```

- "조" 컬럼: group_name이 null이면 `—` 텍스트 (경기 생성 전 또는 조 미배정)
- "주장이름" 컬럼: captain_name이 null이면 `-`
- 출석 체크박스: 체크 상태 = `attended: true`

체크박스 셀:
```tsx
<Table.Cell className="text-center">
  <label className="flex cursor-pointer items-center justify-center">
    <input
      type="checkbox"
      checked={attended}
      onChange={() => handleToggle(teamId)}
      disabled={isPending && pendingTeamId === teamId}
      className="h-4 w-4 rounded border-slate-300 text-amber-500 focus:ring-amber-400 disabled:opacity-50"
    />
  </label>
</Table.Cell>
```

체크박스 토글 피드백:
- 토글 중: 해당 행 체크박스 `disabled + opacity-50`
- 토글 성공: 체크 상태 반영 (optimistic update이므로 즉시 변경)
- 토글 실패: 원래 상태로 롤백 + 행 우측에 `text-xs text-red-500` 에러 메시지 1.5초 표시

**Excel 내보내기 버튼**

```tsx
<a
  href={`/api/admin/tournaments/${tournamentId}/attendance/export`}
  download
>
  <Button variant="secondary">
    <DownloadIcon className="h-4 w-4" />
    Excel 내보내기
  </Button>
</a>
```

- lucide-react의 `Download` 아이콘 사용
- `<a download>` + API route 방식 (서버에서 xlsx Buffer 반환)

**결과 입력 이동 버튼**

```tsx
<div className="flex justify-end">
  <Link href={`/admin/tournaments/${tournamentId}/result`}>
    <Button variant="secondary">결과 입력으로 이동 →</Button>
  </Link>
</div>
```

**인터랙션 목록**

| 인터랙션 | 트리거 | 처리 방식 | 피드백 |
|---------|--------|----------|--------|
| 출석 토글 | 체크박스 onChange | `useTransition` + server action | optimistic update + 실패 시 롤백 |
| Excel 다운로드 | 버튼 클릭 | `<a href download>` → API route | 브라우저 파일 다운로드 |
| 결과 입력 이동 | 버튼 클릭 | `<Link>` → `/result` | 페이지 이동 |

**엣지 케이스**

| 상황 | UI 처리 |
|------|--------|
| 확정 팀 없음 | `EmptyState` 컴포넌트 표시: "확정된 참가팀이 없습니다" |
| 경기 생성 전 (조 미배정) | 조 컬럼 `—` 표시, 기능은 정상 작동 |
| captain_name null | `-` 표시 |
| 출석 토글 중 중복 클릭 | 해당 행 disabled로 방지 |
| API 에러 | 행 우측에 `text-xs text-red-500` 에러 메시지, 체크 상태 롤백 |
| Excel 다운로드 실패 | 현재 범위 외 (브라우저 기본 에러 처리) |
| 대회 종료 상태 | 체크박스 전체 disabled, 읽기 전용으로 표시 (isFinished prop) |

**모바일 대응**

- 테이블 래퍼: `overflow-x-auto` 적용 (가로 스크롤)
- KPI 카드: `grid-cols-1 sm:grid-cols-3`
- Excel 버튼: 모바일에서는 버튼 전체 너비로 변경 고려 (`w-full sm:w-auto`)
- 최소 터치 타깃: 체크박스 레이블 패딩으로 `p-2` 추가하여 터치 영역 확보

## 5. 컴포넌트 설계

| 컴포넌트명 | 파일 경로 | 신규/재사용 | props | 내부 상태 |
|-----------|----------|------------|-------|----------|
| AttendancePage | `app/(app)/admin/tournaments/[id]/attendance/page.tsx` | 신규 | params | 없음 (서버) |
| AttendanceTable | `app/(app)/admin/tournaments/[id]/attendance/AttendanceTable.tsx` | 신규 | `teams: AttendanceRow[]`, `tournamentId: string`, `isFinished: boolean` | `pendingTeamId: string \| null`, `localAttended: Record<string, boolean>`, `errorMessages: Record<string, string>` |
| Button | `components/ui/Button.tsx` | 재사용 | variant | 없음 |
| Card | `components/ui/Card.tsx` | 재사용 | variant | 없음 |
| Badge | `components/ui/Badge.tsx` | 재사용 | variant | 없음 |
| Table, Table.Head 등 | `components/ui/Table.tsx` | 재사용 | — | 없음 |
| EmptyState | `components/ui/EmptyState.tsx` | 재사용 | title, description | 없음 |

### AttendanceTable 컴포넌트 상세

```typescript
// app/(app)/admin/tournaments/[id]/attendance/AttendanceTable.tsx
"use client";

type Props = {
  teams: AttendanceRow[];
  tournamentId: string;
  isFinished: boolean;
};

// 내부 상태
// - localAttended: 각 team_id → attended (optimistic)
// - pendingTeamId: 현재 토글 중인 팀 ID (null이면 없음)
// - errorMessages: 각 team_id → 에러 메시지 문자열

// 초기값: teams 배열에서 { team_id: attended } map으로 초기화
```

**AttendanceRow 타입** (`lib/api/attendance.ts`):
```typescript
export type AttendanceRow = {
  team_id: string;
  team_name: string;
  division_id: string;
  division_name: string;
  division_sort_order: number;
  group_id: string | null;
  group_name: string | null;
  group_order: number | null;
  captain_name: string | null;
  contact: string;
  attended: boolean;
```

## 8. 구현 시 주의사항

### 기존 컴포넌트 변경 시 영향 범위

**`tournamentProgress.ts`**  
- `TournamentProgressState` 타입을 사용하는 모든 곳에서 새 상태 처리 필요
- `resolveNextAction()` 변경으로 대시보드 "다음 행동" 카드의 링크가 SCHEDULE 완료 시 출석 체크 페이지를 가리키게 됨
- 기존 RESULT 진입 경로는 결과 입력 버튼 및 직접 URL 접근으로 유지

**`page.tsx` buildSteps()**  
- 6개 스텝 배열로 변경 — `lg:grid-cols-3` 레이아웃에서 2행 3열 그리드 유지됨
- "결과" 스텝의 active/done 판단 로직은 변경 없음

**`ProgressIndicator.tsx`**  
- 변경 없음. `StepWithActions` 배열을 그대로 받아 렌더링하므로 스텝 수가 늘어나도 동작

### 반응형 처리 우선순위

1. **테이블**: `overflow-x-auto` 필수 — 6개 컬럼은 모바일에서 가로 스크롤
2. **KPI 카드**: `grid-cols-1 sm:grid-cols-3` — 모바일에서 세로 나열
3. **헤더 액션 줄** (h2 + Excel 버튼): `flex flex-col sm:flex-row sm:items-center sm:justify-between gap-2`

### 접근성 고려사항

- 체크박스에 명시적 `aria-label`: `aria-label={`${teamName} 출석 체크`}`
- KPI 요약 카드: 스크린 리더 맥락을 위해 `<section aria-label="출석 요약">` 래핑
- Excel 다운로드 링크: `aria-label="출석 목록 Excel 내보내기"` 추가
- disabled 체크박스(isFinished): `aria-disabled="true"` 명시
- 에러 메시지: `role="alert"` 적용 (1.5초 표시)

## 9. 결론 및 플랜 단계 전달 메모

### 결론

출석 체크 기능은 **신규 파일 6개 + 수정 파일 4개**로 구현 가능하며,  
기존 UI 패턴(page → client component → server action)을 그대로 따르므로 코드 일관성이 유지된다.

핵심 UI 포인트 2가지:
1. **체크박스 optimistic update**: 토글 즉시 로컬 상태 반전 후 서버 액션 결과에 따라 롤백 또는 유지
2. **Excel 다운로드**: `<a download>` + API route로 서버 사이드 xlsx 생성 — 별도 라이브러리 설치 필요

### 플랜 단계 전달 메모

```
[플랜에서 고려할 사항]

1. DB 마이그레이션이 가장 먼저 실행되어야 함 (0255_team_attendance.sql)
   → Supabase MCP tool로 적용 후 API 개발

2. getTeamsWithAttendance() 쿼리 복잡도
   → Supabase SDK 체인으로: tournament_team_applications → teams → profiles → group_teams → groups → team_attendance
   → JOIN이 복잡하므로 단계적으로 처리하거나 RPC 사용 여부 결정 필요

3. TournamentProgressState 변경은 resolveState() 단 한 줄 수정으로 모든 SCHEDULE 완료 케이스에 영향
   → 기존 테스트 케이스가 있다면 확인 필요 (현재 테스트 파일 없음)

4. xlsx 패키지 설치 (npm install xlsx) 필수 — API route 빌드 전 실행

5. isFinished 체크: 대회 종료 후 출석 체크 페이지에서 수정 불가 처리
   → page.tsx에서 tournament.status 조회 후 AttendanceTable에 isFinished prop 전달
```

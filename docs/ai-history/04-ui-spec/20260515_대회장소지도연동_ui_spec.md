# 대회 장소 지도 연동 UI 설계

---

## 1. 리서치 반영 요약

### 기존 UI 패턴에서 재사용할 것

| 항목 | 파일 / 패턴 |
|------|------------|
| 인풋 스타일 | `w-full rounded-md border border-gray-300 px-3 py-2 text-sm` |
| 드롭다운 팝오버 | `absolute left-0 top-full z-10 mt-1 rounded-md border border-gray-200 bg-white shadow-lg` (BasicInfoTab DayPicker 패턴) |
| 클릭 아웃 감지 | `useRef` + `document.addEventListener("mousedown", ...)` (BasicInfoTab, NewTournamentForm) |
| 디바운스 패턴 | `useRef<ReturnType<typeof setTimeout>>` 직접 구현 |
| `useTransition` + Server Action | 저장 버튼 로딩 처리 |
| `MapPin` 아이콘 | `lucide-react` (기존 사용 중) |
| `ExternalLink` 아이콘 | `lucide-react` |
| 폼 필드 간격 | `space-y-1` (라벨↔인풋), `space-y-4` (필드 간) |
| 힌트 텍스트 스타일 | `text-xs text-slate-500` |
| `Card` 컴포넌트 | 섹션 래퍼 |

### 새로 설계할 것

- `LocationAutocomplete` 컴포넌트 (`components/location/LocationAutocomplete.tsx`) — Kakao 자동완성 드롭다운 전체
- `TournamentStickyPanel` 장소 영역 확장 — 지도 링크 2개 (카카오맵, 네이버 지도)
- Kakao API 프록시 라우트 (`app/api/kakao-place-search/route.ts`)

### 기존 패턴에서 의도적으로 변경할 것

| 변경 내용 | 이유 |
|-----------|------|
| 장소 입력을 기존 `<input>` → `LocationAutocomplete` 복합 컴포넌트로 교체 | 자동완성 드롭다운과 좌표 상태 관리가 필요 |
| 지도 링크를 Button이 아닌 `<a>` 태그로 처리 | 새 탭 열기(`target="_blank"`)가 기본 동작이어야 함. `Button` 컴포넌트는 내부 링크 전용 |
| 자동완성 선택 후 직접 편집하면 좌표 초기화 | 좌표와 주소 텍스트가 불일치하면 지도 링크가 엉뚱한 위치를 가리킬 수 있음 |
| 네이버 지도 링크는 좌표 없이도 텍스트 검색으로 노출 | 기존 대회 데이터(좌표 null)에서도 즉시 활용 가능, UX 손실 없음 |

### 2-3. 디자인 토큰 (색상, 폰트, 간격)

**브랜드 색상**:
| 토큰 | 값 | 용도 |
|------|----|------|
| `primary` | `#FF6B00` | 주 브랜드 (주황) |

## 4. 화면별 상세 설계

### 4-1. 대회 편집 — 기본정보 탭 (BasicInfoTab)

**목적**: 관리자가 기존 대회의 장소를 자동완성으로 검색하고 위도/경도와 함께 저장

**레이아웃 구조**:
```
[Card]
  [h2] 기본 정보
  [form]
    [field] 대회명
    [field] 장소  ← 이번 변경 대상
      [LocationAutocomplete]
        [input] 텍스트 입력 (기존 스타일 유지)
        [hint] 좌표 저장 상태 표시 (신규)
        [dropdown] 자동완성 목록 (신규)
    [field] 기간
    [field] 경기 시작 시간
    [field] 대회 소개
    [error/success 메시지]
    [버튼 영역] 저장
```

**인터랙션 흐름**:
1. 관리자가 장소 입력 필드에 2글자 이상 입력
2. 300ms 디바운스 후 `/api/kakao-place-search?q={query}` 호출
3. 로딩 중: 드롭다운에 "검색 중..." 표시
4. 결과 도착: 최대 5개 장소 목록 표시
5. 목록 아이템 클릭: 장소명 → 입력 필드, 위도/경도 → 내부 상태, 드롭다운 닫기
6. 직접 입력 또는 선택 후 텍스트 수정: 좌표 초기화, 힌트 변경
7. 드롭다운 외부 클릭: 드롭다운 닫기
8. 저장 버튼: location + location_lat + location_lng 전달

**힌트 텍스트 상태**:
| 상태 | 힌트 내용 | 색상 |
|------|-----------|------|
| 초기 (텍스트 없음) | (힌트 없음) | — |
| 직접 입력 중 (좌표 없음) | "목록에서 선택하면 지도 링크가 생성됩니다" | `text-slate-400` |
| 자동완성 선택 완료 | "✓ 위치가 선택되었습니다" | `text-emerald-600` |
| 기존 데이터 (텍스트 있지만 좌표 없음) | "목록에서 선택하면 지도 링크가 생성됩니다" | `text-slate-400` |

**엣지 케이스**:
| 케이스 | 처리 방법 |
|--------|-----------|
| 검색 결과 없음 | 드롭다운에 "검색 결과가 없습니다." 표시 |
| API 호출 실패 | 드롭다운에 "검색에 실패했습니다. 직접 입력해 주세요." 표시 |
| 빈 입력 저장 | 기존과 동일하게 null 저장 (좌표도 null) |
| 기존 텍스트 있고 좌표 없는 대회 편집 | 입력 필드에 기존 텍스트 표시, 힌트 "목록에서 선택…" |

**모바일 대응**:
- `LocationAutocomplete` 자체가 `w-full`이므로 별도 처리 불필요
- 드롭다운 최대 높이: `max-h-60 overflow-y-auto` (5개 아이템 기준)
- 모바일 키보드 올라올 때 드롭다운이 뷰포트를 벗어날 수 있음 → `z-50` 적용

### 4-3. 공개 대회 상세 페이지 — TournamentStickyPanel 장소 영역

**목적**: 대회 참가자/관람자가 대회 장소를 지도 앱으로 바로 확인할 수 있도록 링크 제공

**현재 장소 표시 영역** (변경 전):
```tsx
<div className="flex items-center gap-1.5">
  <MapPin size={12} className="shrink-0 text-slate-400" />
  <dd>{tournament.location ?? "미정"}</dd>
</div>
```

**변경 후 레이아웃**:
```
[장소 행]
  [MapPin 아이콘] [장소 텍스트] 또는 "미정"
  [지도 링크 영역] ← 신규 (location 있을 때만)
    [카카오맵 링크] ← 좌표 있을 때만
    [네이버 지도 링크] ← location 텍스트 있을 때
```

**지도 링크 표시 조건**:
| 조건 | 카카오맵 링크 | 네이버 지도 링크 |
|------|-------------|----------------|
| location 있고 lat/lng 있음 | ✅ 표시 | ✅ 표시 |
| location 있고 lat/lng 없음 | ❌ 미표시 | ✅ 표시 |
| location 없음 | ❌ 미표시 | ❌ 미표시 |

**지도 링크 UI 스타일**:
```tsx
{/* 장소 텍스트 행 */}
<div className="flex items-center gap-1.5">
  <MapPin size={12} className="shrink-0 text-slate-400" />
  <dd className="text-xs text-slate-500">{tournament.location ?? "미정"}</dd>
</div>

{/* 지도 링크 행 — location 있을 때만 */}
{hasLocation && (
  <div className="ml-[18px] mt-0.5 flex items-center gap-2">
    {hasCoords && (
      <a
        href={kakaoMapUrl}
        target="_blank"
        rel="noopener noreferrer"
        className="flex items-center gap-0.5 text-[11px] text-amber-600 hover:underline"
      >
        <ExternalLink size={9} />
        카카오맵
      </a>
    )}
    <a
      href={naverMapUrl}
      target="_blank"
      rel="noopener noreferrer"
      className="flex items-center gap-0.5 text-[11px] text-emerald-600 hover:underline"
    >
      <ExternalLink size={9} />
      네이버 지도
    </a>
  </div>
)}
```

**URL 조합**:
```typescript
const kakaoMapUrl = `https://map.kakao.com/link/map/${encodeURIComponent(tournament.location ?? tournament.name)},${tournament.location_lat},${tournament.location_lng}`;
const naverMapUrl = `https://map.naver.com/v5/search/${encodeURIComponent(tournament.location ?? '')}`;
```

**인터랙션**:
- 링크 클릭 → 새 탭으로 외부 지도 앱 열기 (`target="_blank"`)
- hover → `hover:underline`

**엣지 케이스**:
| 케이스 | 처리 |
|--------|------|
| location에 특수문자/한글 포함 | `encodeURIComponent()` 적용 |
| location_lat/lng이 DB에 없는 기존 대회 | 카카오 링크 미표시, 네이버 링크만 표시 |
| location이 null | 링크 영역 전체 미렌더링 |

**모바일 대응**:
- TournamentStickyPanel은 이미 모바일에서 전체 너비 적용
- 링크 영역은 `flex items-center gap-2`로 가로 정렬
- 텍스트가 작아 (`text-[11px]`) 터치 영역 확보를 위해 링크 주변 패딩: `py-0.5`

### `LocationAutocomplete` 상세 설계

**Props 인터페이스**:
```typescript
type KakaoLocalPlace = {
  place_name: string;
  address_name: string;
  road_address_name: string;
  x: string; // 경도 (longitude)
  y: string; // 위도 (latitude)
};

interface LocationAutocompleteProps {
  value: string;
  onChange: (text: string) => void;       // 직접 입력 시 (좌표 초기화 트리거)
  onSelect: (place: KakaoLocalPlace) => void; // 자동완성 선택 시
  hasCoords?: boolean;                     // 현재 좌표 저장 여부 (힌트 표시용)
  placeholder?: string;
  disabled?: boolean;
}
```

**내부 상태**:
```typescript
const [suggestions, setSuggestions] = useState<KakaoLocalPlace[]>([]);
const [isOpen, setIsOpen] = useState(false);
const [isLoading, setIsLoading] = useState(false);
const [apiError, setApiError] = useState<string | null>(null);
const debounceRef = useRef<ReturnType<typeof setTimeout> | null>(null);
const containerRef = useRef<HTMLDivElement>(null);
```

**렌더링 구조**:
```
[div.relative ref={containerRef}]
  [input]  ← 기존 스타일 유지
  [div.absolute.z-50 — 드롭다운]  ← isOpen && (suggestions.length > 0 || isLoading || apiError)
    [로딩 상태] "검색 중..."
    [에러 상태] "검색에 실패했습니다. 직접 입력해 주세요."
    [빈 결과] "검색 결과가 없습니다."
    [결과 목록]
      [ul]
        [li.cursor-pointer.hover:bg-slate-50.px-3.py-2]
          [p.text-sm.font-medium.text-slate-800] place_name
          [p.text-xs.text-slate-400] road_address_name || address_name
  [힌트 텍스트 영역]
    hasCoords → "✓ 위치가 선택되었습니다" (text-xs text-emerald-600)
    !hasCoords && value → "목록에서 선택하면 지도 링크가 생성됩니다" (text-xs text-slate-400)
```

**키보드 접근성**:
| 키 | 동작 |
|----|------|
| `ArrowDown` | 다음 아이템 포커스 |
| `ArrowUp` | 이전 아이템 포커스 |
| `Enter` | 포커스된 아이템 선택 |
| `Escape` | 드롭다운 닫기 |
| `Tab` | 드롭다운 닫기 |

**드롭다운 스타일 상세**:
```
absolute left-0 top-full z-50 mt-1
w-full
rounded-md border border-gray-200 bg-white shadow-lg
max-h-60 overflow-y-auto
```

## 6. 사용자 플로우

### 6-1. 관리자 장소 자동완성 선택 → 저장

```
BasicInfoTab 진입
  → 장소 입력 필드에 텍스트 입력 (2글자+)
    → 300ms 디바운스
      → /api/kakao-place-search 호출
        [성공] → 드롭다운에 최대 5개 목록 표시
          → 아이템 클릭
            → value = place_name
            → locationLat = parseFloat(place.y)
            → locationLng = parseFloat(place.x)
            → hasCoords = true
            → 드롭다운 닫기
            → 힌트: "✓ 위치가 선택되었습니다" (emerald)
            → 저장 버튼 클릭

                [성공] → success 메시지 표시

        [실패] → 드롭다운에 에러 메시지 표시
        [결과 없음] → 드롭다운에 "검색 결과가 없습니다." 표시
  → 드롭다운 외부 클릭 → 드롭다운 닫기
```

## 8. 구현 시 주의사항

### 8-1. 기존 컴포넌트 변경 시 영향 범위

- `lib/api/tournaments.ts`의 타입 변경은 프로젝트 전체에서 가장 많이 import되는 파일이나, **기존 필드 삭제 없이 신규 추가**이므로 TypeScript breaking change 없음.
- `TournamentStickyPanel`은 `PublicTournamentRow` 타입을 prop으로 받으므로, 타입에 좌표 필드가 추가되면 자동으로 사용 가능. 별도 prop 변경 없이 컴포넌트 내부 조건 분기만 추가.
- `BasicInfoTab`은 `tournament: TournamentEditRow`에서 초기값을 읽으므로, 타입 확장 후 `tournament.location_lat ?? null`로 초기 상태 설정 가능.

### 8-2. 반응형 처리 우선순위

1. `LocationAutocomplete` 드롭다운: `w-full`로 부모 너비 따름. 모바일 키보드 올라올 때 뷰포트 이탈 방지를 위해 `z-50` 적용.
2. `TournamentStickyPanel` 지도 링크: 이미 모바일 풀너비이므로 별도 처리 불필요. 두 링크가 좁은 화면에서도 `gap-2` 간격으로 가로 나열 가능.
3. `NewTournamentForm` Step 0: 폼 자체가 단일 칼럼이므로 `w-full` 유지.

### 8-3. 접근성 고려사항

- `LocationAutocomplete` 드롭다운:
  - `role="listbox"` + `role="option"` ARIA 속성 적용
  - 키보드 네비게이션: ArrowUp/Down, Enter, Escape
  - 로딩 상태: `aria-busy="true"`
- 지도 링크:
  - `target="_blank"` 링크에 `rel="noopener noreferrer"` 필수 (보안)
  - 스크린 리더용 `aria-label="카카오맵에서 위치 보기 (새 창)"` 추가 권장

### 8-4. API 키 관리

- Kakao REST API 키는 `KAKAO_LOCAL_REST_API_KEY` (서버 전용, `NEXT_PUBLIC_` 없음)으로 `.env.local`에 추가
- `app/api/kakao-place-search/route.ts`에서만 참조
- Vercel 배포 시 환경변수 등록 필요

### 8-5. [QUESTION] TournamentCard 링크 노출 여부

목록 카드(`TournamentCard.tsx`)에도 네이버 지도 링크를 노출할지 결정 필요.
- **노출 시**: 목록에서 바로 장소 확인 가능, 카드 높이 증가
- **미노출 시**: 상세 페이지에서만 확인, 카드 레이아웃 변화 없음

현재 요구사항은 공개 상세 페이지만 명시했으므로 **기본 미노출**로 설계. 필요 시 추가.

### 8-6. [QUESTION] 자동완성 검색 결과 수

현재 Kakao Local API 기본 15개 반환. 드롭다운 UX 상 **5개로 제한** 권장 (`?size=5`). 더 많은 결과가 필요하면 "더 보기" 패턴 추가 가능 (이번 범위 제외).

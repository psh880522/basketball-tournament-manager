## 1. 리서치 반영 요약

### 기존 UI 패턴에서 재사용할 것

| 항목 | 재사용 근거 |
|------|------------|
| `components/ui/Button` (primary / secondary / ghost variant) | OAuth 버튼 기반 스타일 참조 |
| `components/ui/Card` | 로그인/회원가입 폼 래퍼 유지 |
| `app/(auth)/layout.tsx` (`GlobalHeader minimal`) | 약관 동의 페이지도 동일 레이아웃 |
| 에러 표시 패턴 (`rounded-lg border border-red-200 bg-red-50`) | OAuth 에러 메시지 표시 |
| `space-y-4` / `w-full` / `max-w-sm` 폼 패턴 | 약관 동의 폼, OAuth 버튼 배치 |
| 약관 동의 섹션 UI (회원가입 폼 내 체크박스 영역) | `/terms` 페이지 그대로 복제 |
| `useTransition` + 버튼 비활성화 패턴 | OAuth 버튼 로딩 상태 |

### 새로 설계할 것

| 항목 | 설명 |
|------|------|
| `components/auth/OAuthButtons.tsx` | Google / Kakao 버튼 Client Component |
| `components/auth/OAuthDivider.tsx` | "또는" 구분선 컴포넌트 |
| `app/(auth)/terms/page.tsx` | OAuth 신규 유저 약관 동의 페이지 |
| `app/(auth)/terms/Form.tsx` | 약관 동의 Client Form 컴포넌트 |
| `app/(auth)/terms/actions.ts` | 약관 동의 저장 서버 액션 |
| 로그인 페이지 URL 에러 파라미터 표시 | `searchParams.error` 처리 Server Component 로직 |

### 기존 패턴에서 의도적으로 변경할 것

| 항목 | 변경 내용 | 이유 |
|------|-----------|------|
| 회원가입 페이지 subtitle | "이메일과 비밀번호로 계정을 만드세요." → "소셜 계정 또는 이메일로 시작하세요." | OAuth 추가로 두 가지 방식 제공 |
| 로그인 폼 순서 | OAuth 버튼 상단 → 구분선 → 이메일 폼 하단 | OAuth가 더 간편하므로 상단 배치가 일반적인 UX 관행 |

## 2. 기존 UI 패턴 분석

### 2-1. 사용 중인 UI 라이브러리 및 컴포넌트

**shadcn/ui 미사용 — 전체 커스텀 컴포넌트 라이브러리**

| 컴포넌트 | 경로 | 현재 사용처 |
|---------|------|-----------|
| `Button` | `components/ui/Button.tsx` | 모든 폼 제출, CTA |
| `Input` | `components/ui/Input.tsx` | 이메일, 비밀번호 등 입력 |
| `Card` | `components/ui/Card.tsx` | 폼 래퍼, 콘텐츠 블록 |
| `Toast` | `components/ui/Toast.tsx` | 성공/실패 알림 |
| `BottomSheet` | `components/ui/BottomSheet.tsx` | 모바일 필터, 액션 시트 |
| `Badge` | `components/ui/Badge.tsx` | 상태 표시 |

**아이콘**: 외부 라이브러리 없음, 모두 **inline SVG** (Heroicons 스타일, strokeLinecap round)

### 2-2. 레이아웃 패턴

**Auth 페이지 공통 레이아웃:**
```
GlobalHeader (minimal: 로고만, h-16, sticky top-0)
main.min-h-[calc(100vh-3.5rem)].bg-gray-50.px-4.py-12
  div.mx-auto.w-full.max-w-sm.space-y-6
    [상단 요소: 스텝 인디케이터 or 스페이서]
    div.space-y-1.text-center
      h1.text-2xl.font-bold.text-slate-900 (타이틀)
      p.text-sm.text-slate-500 (서브타이틀)
    Card
      [폼 내용]
    p.text-center.text-sm.text-slate-500 (하단 링크)
```

**Card 내부 폼 패턴:**
```
form.space-y-4
  [에러 박스 (조건부)]
  [입력 필드들]
  [제출 버튼 w-full]
```

### 2-3. 디자인 토큰 (색상, 폰트, 간격)

**Brand Colors:**
- 주요 강조색 (Orange): `#FF6B00`, gradient: `from-[#FF6B00] to-[#FF8C33]`
- 링크/포커스: `amber-600` (#d97706), hover: `amber-500`
- 입력 포커스 링: `amber-400`

**Surface Colors:**
- 페이지 배경: `bg-gray-50` (#f9fafb)
- 카드/흰 영역: `bg-white`
- 경계선: `border-slate-200`

**Text Colors:**
- 기본 텍스트: `text-slate-900`
- 보조 텍스트: `text-slate-500`, `text-slate-600`
- 에러: `text-red-700`

**Button Variants:**
- `primary`: `bg-gradient-to-br from-[#FF6B00] to-[#FF8C33] text-white`
- `secondary`: `border border-[#FF6B00]/30 bg-transparent text-[#FF6B00]`
- `ghost`: `text-slate-600 hover:bg-surface-low`

**Border Radius:**
- 버튼: `rounded-[4px]` (4px)
- 입력 필드: `rounded-lg` (8px)
- 카드: `rounded-xl` (12px)
- 에러 박스: `rounded-lg`

**Spacing System:**
- 폼 필드 간격: `space-y-4`
- 카드 패딩: `p-5`
- 버튼 패딩: `px-4 py-2`

**Font:**
- 제목류: Space Grotesk
- 본문: Inter

## 4. 화면별 상세 설계

### 4-1. 로그인 페이지 (`/login`)

#### 목적
기존 이메일/비밀번호 로그인에 Google, Kakao OAuth 버튼을 추가해 사용자가 더 빠르게 로그인할 수 있게 한다.

#### 레이아웃 구조

```
GlobalHeader (minimal)
main.min-h-[calc(100vh-3.5rem)].bg-gray-50.px-4.py-12
  div.mx-auto.w-full.max-w-sm.space-y-6
    ┌── h-9 (spacer) ──────────────────────────────┐
    │                                               │
    ├── 텍스트 블록 (text-center) ─────────────────┤
    │   h1 "로그인"                                 │
    │   p "소셜 계정 또는 이메일로 로그인하세요."      │  ← 텍스트 변경
    │                                               │
    ├── Card ──────────────────────────────────────┤
    │  ┌─────────────────────────────────────────┐ │
    │  │ [에러 박스 — URL error param 표시 (조건부)] │ │
    │  │                                         │ │
    │  │ OAuthButtons (mode="login")             │ │
    │  │   [G] Google로 계속하기                  │ │
    │  │   [K] 카카오로 계속하기                   │ │
    │  │                                         │ │
    │  │ OAuthDivider ("또는")                   │ │
    │  │                                         │ │
    │  │ Input (이메일)                           │ │
    │  │ Input (비밀번호 + 눈 아이콘)              │ │
    │  │   [비밀번호를 잊으셨나요?] 링크           │ │
    │  │ Button "로그인" (primary, w-full)        │ │
    │  └─────────────────────────────────────────┘ │
    │                                               │
    └── p "계정이 없으신가요? 회원가입" ────────────┘
```

#### 컴포넌트 목록

| 컴포넌트 | 신규/재사용 | 역할 |
|---------|-----------|------|
| `OAuthButtons` | **신규** | Google/Kakao 버튼 그룹 |
| `OAuthDivider` | **신규** | "또는" 구분선 |
| `LoginForm` | 재사용 (수정) | 이메일 폼 + OAuth 에러 표시 추가 |
| `Input` | 재사용 | 이메일, 비밀번호 |
| `Button` | 재사용 | 로그인 제출 |
| `Card` | 재사용 | 폼 래퍼 |

#### 인터랙션

**[1] OAuth 버튼 클릭:**
- 클릭 즉시 해당 버튼 loading 상태 (`disabled`, 텍스트 변경)
- 다른 버튼도 `disabled` 처리 (중복 클릭 방지)
- `supabase.auth.signInWithOAuth({ provider, options: { redirectTo } })` 호출
- 브라우저가 provider 인증 페이지로 리다이렉트 (React state 소멸)

**[2] OAuth 에러 반환 (URL param):**
- `/login?error=...` 형태로 콜백에서 리다이렉트됨
- `page.tsx` (Server Component)에서 `searchParams.error` 읽어 `Card` 상단에 에러 박스 표시
- 에러 코드 → 한국어 메시지 번역 (아래 섹션 참조)

**[3] 이메일 폼 제출:**
- 기존 동작 유지 (변경 없음)

#### OAuth URL 에러 파라미터 번역

| `error` 파라미터 값 | 표시 메시지 |
|--------------------|-----------|
| `link_expired` | "링크가 만료되었습니다. 다시 로그인해주세요." |
| `missing_code` | "인증 코드가 없습니다. 다시 시도해주세요." |
| `oauth_cancelled` | "로그인이 취소되었습니다." |
| `oauth_provider_error` | "소셜 로그인 중 오류가 발생했습니다. 다시 시도해주세요." |
| `email_conflict` | "동일한 이메일로 이미 가입된 계정이 있습니다. 이메일 로그인을 이용하세요." |
| 기타 | "로그인 중 오류가 발생했습니다. 다시 시도해주세요." |

#### 엣지 케이스

| 케이스 | 처리 |
|--------|------|
| 이미 로그인된 상태 | 기존대로 `login/page.tsx` Server Component에서 역할별 리다이렉트 |
| OAuth 취소 후 복귀 | URL `error=oauth_cancelled` → 에러 박스 표시 |
| 동일 이메일 계정 충돌 | URL `error=email_conflict` → 이메일 로그인 안내 |
| provider 서비스 장애 | URL `error=oauth_provider_error` → 재시도 안내 |

#### 모바일 대응

- `max-w-sm`(28rem)이 모바일 화면 너비보다 크지 않으므로 자연스럽게 반응형
- OAuth 버튼은 `w-full` 풀 너비
- 터치 영역: 버튼 높이 최소 44px 확보 (`py-2.5` 이상)
- 카카오 앱 설치 여부에 따라 앱 전환 발생 — UX 변경 없음 (기기 제어 영역)

### 4-2. 회원가입 페이지 (`/signup`)

#### 목적
OAuth 가입을 이메일 가입과 동등한 첫 번째 선택지로 제공한다. 이메일 가입 폼은 "또는" 구분선 아래로 이동.

#### 레이아웃 구조

```
GlobalHeader (minimal)
main.min-h-[calc(100vh-3.5rem)].bg-gray-50.px-4.py-12
  div.mx-auto.w-full.max-w-sm.space-y-6
    ┌── OnboardingStepIndicator (currentStep="signup") ┐
    │                                                   │
    ├── 텍스트 블록 (mt-8, text-center) ───────────────┤
    │   h1 "회원가입"                                   │
    │   p "소셜 계정 또는 이메일로 시작하세요."            │  ← 텍스트 변경
    │                                                   │
    ├── Card ─────────────────────────────────────────┤
    │  ┌───────────────────────────────────────────┐  │
    │  │ OAuthButtons (mode="signup")               │  │
    │  │   [G] Google로 시작하기                    │  │
    │  │   [K] 카카오로 시작하기                     │  │
    │  │                                           │  │
    │  │ OAuthDivider ("또는 이메일로 시작하기")     │  │
    │  │                                           │  │
    │  │ [에러 박스 (조건부)]                        │  │
    │  │ Input (이메일)                             │  │
    │  │ Input (비밀번호 + 눈 아이콘)                │  │
    │  │ Input (비밀번호 확인 + 눈 아이콘)           │  │
    │  │ [약관 동의 섹션 — 기존 그대로]              │  │
    │  │ Button "회원가입" (primary, w-full)        │  │

> **[QUESTION]** OAuth 버튼에 terms notice 문구를 추가할지 결정 필요.  
> 예: 버튼 하단에 `text-xs text-slate-400` 로 "가입 시 서비스 이용약관 및 개인정보처리방침에 동의하게 됩니다."  
> → `/terms` 페이지에서 따로 수집하는 방식(Research 권장 A안)이므로, 이 문구는 생략하고 약관 동의 페이지에서 처리.

#### 컴포넌트 목록

| 컴포넌트 | 신규/재사용 | 역할 |
|---------|-----------|------|
| `OAuthButtons` | **신규** | Google/Kakao 버튼 그룹 |
| `OAuthDivider` | **신규** | "또는 이메일로 시작하기" 구분선 |
| `SignupForm` | 재사용 (수정) | 이메일 폼 (OAuthButtons + OAuthDivider 추가) |
| `OnboardingStepIndicator` | 재사용 | 진행 단계 표시 |

#### 인터랙션

**[1] OAuth 버튼 클릭 (회원가입 경우):**
- `signInWithOAuth()` 호출, `redirectTo = /auth/callback?next=/terms`
- 콜백에서 신규 유저 → `/terms` 페이지로 이동
- 콜백에서 기존 유저 → 역할 기반 리다이렉트 (`/dashboard`, `/admin`, `/`)

**[2] 이메일 폼 제출:**
- 기존 동작 유지 (약관 동의 → 이메일 확인)

#### 엣지 케이스

| 케이스 | 처리 |
|--------|------|
| 이미 가입된 Google 계정 재가입 시도 | 기존 유저로 처리 → 콜백에서 역할 기반 리다이렉트 |
| 동일 이메일 계정 충돌 | 콜백에서 `/login?error=email_conflict` 리다이렉트 |

#### 모바일 대응

- 로그인 페이지와 동일 (max-w-sm, w-full 버튼)

### 4-3. 약관 동의 페이지 (`/terms`) — **신규**

#### 목적
OAuth 로그인으로 신규 가입한 사용자의 서비스 이용약관 및 개인정보처리방침 동의를 수집한다.  
이메일 가입 시 `SignupForm` 내에서 처리하던 것과 동등한 수준의 동의를 OAuth 경로에서도 확보한다.

#### 접근 조건
- 인증 세션이 존재하는 상태 (`getUserWithRole()` status가 `unauthenticated`가 아님)
- `user_terms_consents` 테이블에 해당 유저의 `service` + `privacy` 레코드가 없는 경우 (신규 유저)
- `next` query param: 동의 완료 후 이동할 경로 (기본값: `/onboarding/completion?step=signup`)

#### 레이아웃 구조

```
GlobalHeader (minimal)
main.min-h-[calc(100vh-3.5rem)].bg-gray-50.px-4.py-12
  div.mx-auto.w-full.max-w-sm.space-y-6
    ┌── 텍스트 블록 (text-center) ──────────────────────┐
    │   h1 "서비스 이용 동의"                           │
    │   p "23Board를 이용하기 전 아래 약관에 동의해주세요."│
    │                                                   │
    ├── Card ─────────────────────────────────────────┤
    │  ┌───────────────────────────────────────────┐  │
    │  │ [에러 박스 (조건부)]                        │  │
    │  │                                           │  │
    │  │ 약관 동의 섹션 (SignupForm과 동일 구조)     │  │
    │  │  ┌──────────────────────────────────────┐ │  │
    │  │  │ [✓] 전체 동의                         │ │  │
    │  │  │ ──────────────────────────────────   │ │  │
    │  │  │ [✓] [필수] 서비스 이용약관 동의  전문▶ │ │  │
    │  │  │ [✓] [필수] 개인정보처리방침 동의 전문▶ │ │  │

      → next 경로 or 홈으로 (단, 필수 약관 미동의 시 일부 기능 제한 안내)
```

> **[QUESTION]** "나중에 동의하기" 링크 제공 여부:  
> - 필수 약관 미동의 상태는 서비스 이용 불가가 원칙이라면 → 링크 제거, 필수 동의 강제  
> - 최소한 서비스 탐색은 허용한다면 → 링크 유지, 일부 기능 제한  
> 이 UI 설계에서는 **링크 유지** 방향으로 설계하되, 구현 시 정책 결정 필요.

#### 컴포넌트 목록

| 컴포넌트 | 신규/재사용 | 역할 |
|---------|-----------|------|
| `TermsConsentForm` | **신규** | 약관 동의 Client Form |
| `Card` | 재사용 | 폼 래퍼 |
| `Button` | 재사용 | 제출 버튼 |
| 약관 체크박스 영역 | 재사용 패턴 | `SignupForm` 내 약관 섹션과 동일 구조 |

#### 인터랙션

**[1] 약관 체크:**
- 전체 동의 → 3개 모두 체크
- 개별 체크박스 상태에 따라 "전체 동의" 체크 자동 연동

**[2] "동의하고 시작하기" 클릭:**
- `isPending` 동안 버튼 비활성화, 텍스트 "저장 중..."
- 서버 액션 `saveTermsConsentAction()` 호출 → `recordTermsConsentBatch()` 실행
- 성공 → `redirect(next ?? "/onboarding/completion?step=signup")`
- 실패 → 에러 박스 표시

**[3] "나중에 동의하기" 클릭:**
- `next` 파라미터 경로 or `/` 로 이동
- 약관 미동의 상태 유지

#### 엣지 케이스

| 케이스 | 처리 |
|--------|------|
| 비인증 상태 접근 | `page.tsx` Server Component에서 `/login` 리다이렉트 |
| 이미 약관 동의한 유저 | `next` 경로로 즉시 리다이렉트 (약관 폼 보여주지 않음) |
| 필수 약관 미체크 상태 제출 | 에러 박스: "필수 약관에 동의해주세요." |
| `next` 파라미터 없음 | 기본값 `/onboarding/completion?step=signup` |

#### 모바일 대응

- 동일한 max-w-sm 레이아웃
- 체크박스 터치 영역 충분히 확보 (label 전체 클릭 가능)

export default async function TermsPage({ searchParams }: Props) {

          </p>
        </div>

          <TermsConsentForm next={next ?? "/onboarding/completion?step=signup"} />
        </Card>
      </div>
    </main>
  );
}

## 6. 사용자 플로우

### 6-1. Google 로그인 — 기존 유저

```
/login 페이지
  → [Google로 계속하기] 클릭
  → OAuthButtons: supabase.auth.signInWithOAuth({ provider: "google", redirectTo: ".../auth/callback?next=/dashboard" })
  → 브라우저: Google 인증 페이지로 리다이렉트
  → Google 인증 완료
  → /auth/callback?code=xxx&next=/dashboard
  → exchangeCodeForSession(code)
  → 기존 유저 감지 (created_at이 10초 이상 이전)
  → getUserWithRole() 호출
  → player → /dashboard 리다이렉트
  → manager/organizer → /admin 리다이렉트
  → user (선수 등록 미완료) → /onboarding/completion?step=signup 리다이렉트
```

### 6-2. Google 로그인 — 신규 유저 (회원가입)

```
/signup 페이지
  → [Google로 시작하기] 클릭
  → supabase.auth.signInWithOAuth({ provider: "google", redirectTo: ".../auth/callback?next=/terms" })
  → Google 인증 페이지 → 인증 완료
  → /auth/callback?code=xxx&next=/terms
  → exchangeCodeForSession(code)
  → 신규 유저 감지 (created_at이 10초 이내)
  → /terms?next=/onboarding/completion?step=signup 리다이렉트
  → /terms 페이지: 약관 동의 폼 표시
  → [필수 체크] + [동의하고 시작하기] 클릭
  → saveTermsConsentAction() → recordTermsConsentBatch() 저장
  → /onboarding/completion?step=signup 리다이렉트
  → [선수 등록 시작하기] CTA 표시
```

### 6-3. Kakao 로그인 — 이메일 없는 신규 유저

```
/signup 또는 /login 페이지
  → [카카오로 시작하기/계속하기] 클릭
  → supabase.auth.signInWithOAuth({ provider: "kakao", ... })
  → 카카오 인증 페이지 → 이메일 제공 거부
  → /auth/callback?code=xxx
  → exchangeCodeForSession(code) → auth.users.email = null
  → handle_new_user() 트리거 → profiles 행 생성 (role='user')
  → 신규 유저 → /terms 리다이렉트
  → 약관 동의 완료 → /onboarding/completion?step=signup
  ↓
  (ProfilePopup 표시 시: email=null → "사용자" 텍스트, "?" 아바타 — 기존 코드 대응됨)
```

### 6-4. OAuth 취소 / 에러 케이스

```
OAuth 진행 중 취소 또는 에러 발생
  → /auth/callback에 error_code 또는 error param 포함 반환
  → route.ts: error 감지 → /login?error=[에러코드] 리다이렉트
  → /login 페이지: searchParams.error 읽기
  → LoginForm에 initialError prop 전달
  → Card 상단에 에러 박스 표시
```

### 6-5. 동일 이메일 계정 충돌

```
이메일/비밀번호 기존 가입 계정 → Google OAuth 로그인 시도
  → /auth/callback: error 발생

## 8. 구현 시 주의사항

### 8-1. 기존 컴포넌트 변경 시 영향 범위

**`app/(auth)/login/Form.tsx` 수정 영향:**
- `LoginForm`은 `app/(auth)/login/page.tsx`에서만 사용됨 → 영향 범위 최소
- `initialError` prop 추가 시 기존 사용처에서 prop 없이도 동작 (optional)

**`app/(auth)/signup/Form.tsx` 수정 영향:**
- `SignupForm`은 `app/(auth)/signup/page.tsx`에서만 사용됨 → 영향 범위 최소
- `OAuthButtons` / `OAuthDivider` 추가는 기존 이메일 폼 로직 변경 없음

**`app/auth/callback/route.ts` 수정 영향:**
- 이 파일은 이메일 확인 링크, 비밀번호 재설정 링크, OAuth 콜백 모두에서 사용됨
- 신규 분기 로직이 기존 `next` 파라미터 리다이렉트와 충돌하지 않도록 주의
- 비밀번호 재설정 플로우 (`?next=/reset-password`)는 별도 분기 유지 필요

### 8-2. 반응형 처리 우선순위

1. **최우선**: 버튼 터치 영역 최소 44px (`py-2.5` 이상)
2. **Google/Kakao 로고 SVG**: 모바일에서도 18px 유지 (벡터이므로 자동 선명)
3. `max-w-sm` 컨테이너가 모바일에서 `px-4`로 여백 확보 → 별도 breakpoint 불필요
4. 카카오 앱 전환 시 iOS/Android 네이티브 동작 — 추가 처리 없음

### 8-3. 접근성 고려사항

| 요소 | 처리 방법 |
|------|----------|
| Google 버튼 로고 SVG | `aria-hidden="true"` 적용, 버튼 텍스트로 의미 전달 |
| Kakao 버튼 로고 SVG | 동일 |
| 로딩 상태 버튼 | `disabled` + `aria-busy="true"` |
| 에러 박스 | `role="alert"` 추가 (스크린리더 즉시 읽기) |
| 약관 체크박스 | `<label>` 연결 유지 (기존 SignupForm 패턴 동일) |
| OAuthDivider | `role="separator"` 또는 `aria-hidden="true"` (장식적 요소) |

### 8-4. 보안 고려사항

- `redirectTo` URL에 외부 도메인이 들어가지 않도록 Supabase Dashboard에서 Redirect URL 화이트리스트 관리
- `next` param으로 외부 URL 전달 방지: 콜백 라우트에서 `/`로 시작하는 경로만 허용
  ```typescript
  const safeNext = next?.startsWith("/") ? next : "/dashboard";
  ```

1. **약관 동의 페이지의 "나중에 동의하기" 링크 제공 여부** 결정 필요

   → 이미 `signUpWithPassword()`에서 사용 중이므로 `.env.local` 및 Vercel 대시보드에 설정되어 있어야 함

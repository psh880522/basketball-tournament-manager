# 대회 결과 페이지 UI 설계

---

## 1. 리서치 반영 요약

### 기존 UI 패턴에서 재사용할 것

| 항목 | 파일 / 패턴 |
|------|------------|
| 페이지 외부 래퍼 | `min-h-screen bg-gray-50 px-4 py-8` |
| 컨텐츠 래퍼 | `mx-auto max-w-5xl space-y-4` (공개 결과 페이지는 max-w-4xl이 아닌 5xl 사용) |
| 뒤로 가기 링크 | `text-sm text-gray-500` (← 대회 상세) |
| `Card` 컴포넌트 | 대회 헤더, 챔피언 배너 (`default` / `highlight` variant) |
| `Table` compound 컴포넌트 | 조별 순위표 |
| `Badge` 컴포넌트 | 매치 상태 표시 (완료/진행중/미완료) |
| `EmptyState` 컴포넌트 | 브래킷 없음, 순위 없음 |
| `DragScroll` 컴포넌트 | 브래킷 수평 드래그 스크롤 |
| 에러 패턴 | `text-sm text-red-600` |
| Suspense fallback | 서버 컴포넌트 로딩 중 표시 |

### 새로 설계할 것

- `ChampionBanner.tsx` — 우승팀 강조 배너 (트로피 아이콘 + 팀명)
- `ResultTabs.tsx` — "대진표 / 조별 순위" 탭 전환 클라이언트 컴포넌트
- `TournamentBracket.tsx` — 좌→우 수평 트리 브래킷 시각화
- `BracketMatchCard.tsx` — 브래킷 내 개별 경기 카드
- `StandingsTable.tsx` — 조별 순위 테이블 (league 그룹 필터링 포함)

### 기존 패턴에서 의도적으로 변경할 것

| 변경 내용 | 이유 |
|-----------|------|
| `max-w-5xl` 사용 (기존 admin 페이지는 `max-w-4xl`) | 브래킷은 가로 공간이 넓어야 읽기 편함. 공개 전시 페이지이므로 더 넓은 레이아웃이 적합 |
| 인라인 style 전체 제거 → Tailwind 클래스로 교체 | 프로젝트 전체 스타일 규칙과 일치시킴 |
| 탭(Tab) UI 도입 (기존: 섹션 스크롤) | 브래킷과 순위를 동시에 보여주면 스크롤이 매우 길어짐. 탭으로 분리하면 모바일 UX 개선 |
| 디비전별로 브래킷을 분리 렌더링 (기존: 전체 혼합) | 복수 디비전 시 경기가 섞이는 버그 해결. FIBA/Challonge 방식과 일치 |
| 챔피언 배너를 별도 카드로 강조 (기존: 텍스트 나열) | Start.gg / FIBA 벤치마킹 — 우승팀은 시각적으로 가장 강조되어야 함 |
| `DragScroll` 컴포넌트로 브래킷 감싸기 | 수평 스크롤 브래킷을 마우스 드래그로 탐색 가능하게 함 (이미 schedule 페이지에서 사용 중) |

## 2. 기존 UI 패턴 분석

### 2-1. 사용 중인 UI 라이브러리 및 컴포넌트

**외부 라이브러리**: `tailwindcss 4`, `lucide-react`, `@dnd-kit/*` (DnD용)  
**shadcn, MUI 없음** — 모든 UI 컴포넌트는 `components/ui/`에 직접 구현

| 컴포넌트 | 파일 경로 | variant / 주요 props |
|---------|-----------|---------------------|
| `Button` | `components/ui/Button.tsx` | `primary \| secondary \| ghost` |
| `Card` | `components/ui/Card.tsx` | `default \| highlight \| muted` |
| `Badge` | `components/ui/Badge.tsx` | `default \| success \| warning \| danger \| info \| live` |
| `Table` | `components/ui/Table.tsx` | compound pattern: `.Head .HeadCell .Body .Row .Cell` |
| `EmptyState` | `components/ui/EmptyState.tsx` | `message: string` |
| `Toast` | `components/ui/Toast.tsx` | `success \| error \| info` + auto-close 3s |
| `DragScroll` | `components/ui/DragScroll.tsx` | `children`, `className` — 마우스 드래그 수평 스크롤 |

### 2-2. 레이아웃 패턴

**공개 페이지 공통 구조** (apply, tournament detail 참고):
```tsx
<main className="min-h-screen bg-gray-50 px-4 py-8">
  <div className="mx-auto max-w-5xl space-y-4">
    <Link href={`/tournament/${id}`} className="text-sm text-gray-500">
      ← 대회 상세
    </Link>
    <h1 className="text-2xl font-semibold">[대회명]</h1>
    {/* 컨텐츠 */}
  </div>
</main>
```

**서버/클라이언트 분리 패턴**:
- `page.tsx`: 서버 컴포넌트 — 인증, 데이터 fetch, Suspense 래핑
- `components/[Name].tsx`: 클라이언트 컴포넌트 — 탭 전환 등 인터랙션
- 데이터는 서버에서 모두 fetch → props로 클라이언트에 전달 (탭 전환 시 추가 요청 없음)

### 2-3. 디자인 토큰 (색상, 폰트, 간격)

**색상**

| 용도 | 클래스 / 값 |
|------|------------|
| 페이지 배경 | `bg-gray-50` |

| 용도 | 클래스 |
|------|--------|

## 4. 화면별 상세 설계

### 4-1. 대회 결과 페이지 (공개)

**목적**  
대회가 종료(closed/finished)된 후, 참가팀·관람객·관계자가 토너먼트 브래킷과 조별 순위를 확인한다.  
우승팀 배너로 결과를 한눈에 파악하고, 탭으로 상세 정보를 전환한다.

**사용자 시나리오**
1. 참가자가 대회 상세 페이지에서 "결과 보기" 링크 클릭 → 결과 페이지 진입
2. 우승팀 배너로 결과를 빠르게 파악
3. "대진표" 탭에서 브래킷 전체 흐름 확인
4. "조별 순위" 탭에서 리그 순위 확인
5. organizer는 `open` 상태에서도 접근 가능 (결과 미리보기 용도)

**브래킷 레이아웃 (TournamentBracket 내부):**

수평 트리 구조. 각 라운드는 하나의 "열(column)"이며, 왼쪽에서 오른쪽으로 시간 순서대로 표시한다.

```
DragScroll (드래그 수평 스크롤)
└── overflow-x-auto py-4
    └── flex flex-row items-start gap-0 (브래킷 행)
        ├── BracketRoundColumn (16강)
        │   ├── BracketRoundLabel "16강"
        │   └── BracketMatchGroup[] (8 pairs)
        ├── BracketRoundColumn (8강)
        │   ├── BracketRoundLabel "8강"
        │   └── BracketMatchGroup[] (4 pairs)
        ├── BracketRoundColumn (4강)
        │   ├── BracketRoundLabel "4강"
        │   └── BracketMatchGroup[] (2 pairs)
        ├── BracketRoundColumn (3/4위전) — 결승 열과 나란히 표시
        │   ├── BracketRoundLabel "3/4위전"
        │   └── BracketMatchGroup[] (1 match)
        └── BracketRoundColumn (결승)
            ├── BracketRoundLabel "결승"
            └── BracketMatchGroup[] (1 match)
```

**브래킷 연결선 방식:**

각 라운드 열 사이에 연결선을 시각적으로 표시한다.  
CSS border를 이용한 순수 HTML/Tailwind 방식:

```
[매치 카드 A] ──────┐
                     │ (수직선: border-r)
[매치 카드 B] ──────┘──────── [다음 라운드 매치 카드]
```

```tsx
// BracketMatchPair: 2개 매치 카드 + 연결선 + 다음 라운드 입력선
<div className="flex items-stretch">
  {/* 매치 카드 쌍 */}
  <div className="flex flex-col">
    <div className="flex items-center">
      <BracketMatchCard match={matches[0]} />
      <div className="h-px w-4 bg-gray-300" />  {/* → 수평선 */}
    </div>
    <div className="ml-[w_of_card] w-4 flex-1 border-r border-gray-300" />  {/* ↕ 수직선 */}
    <div className="flex items-center">
      <BracketMatchCard match={matches[1]} />
      <div className="h-px w-4 bg-gray-300" />  {/* → 수평선 */}
    </div>
  </div>
  {/* 다음 라운드 입력선 */}
  <div className="h-px w-4 self-center bg-gray-300" />
</div>
```

**BracketMatchCard 상세:**

```

// 팀명: truncate max-w-[7rem]

// 아직 배정 안 된 팀 (TBD):
// bg-white, 팀명: "미정", 점수: "-", 전체 텍스트: text-gray-300

```

**경기 상태별 카드 스타일:**

| 상태 | teamA 행 | teamB 행 | 비고 |
|------|----------|----------|------|
| `completed` + 승자 A | `bg-orange-50 border-l-2 border-[#FF6B00]` | `bg-white text-gray-400` | 점수 표시 |
| `completed` + 승자 B | `bg-white text-gray-400` | `bg-orange-50 border-l-2 border-[#FF6B00]` | 점수 표시 |
| `scheduled` / 미완료 | `bg-white` | `bg-white` | 점수 "-" |
| 팀 미배정 (TBD) | `bg-white text-gray-300` | `bg-white text-gray-300` | 팀명 "미정", 점수 "-" |

**라운드 레이블 (BracketRoundLabel):**

```tsx
// 각 열 상단
<div className="mb-2 text-center text-xs font-semibold uppercase tracking-wide text-slate-500 w-44">
  {roundLabel}  // "16강" "8강" "4강" "3/4위전" "결승"
</div>
```

**라운드 열 간 간격:**

라운드 진행에 따라 매치 카드 간 수직 간격이 증가하여 연결선이 자연스러워야 한다.

| 라운드 | 매치 수 | 카드 간 수직 gap |
|--------|---------|----------------|
| 16강 | 8 | `gap-2` (8px) |
| 8강 | 4 | `gap-10` (40px) — 16강 2매치 높이 + gap |
| 4강 | 2 | `gap-28` (112px) — 8강 2매치 높이 + gap |
| 결승 | 1 | 수직 중앙 정렬 |
| 3/4위전 | 1 | 4강 행과 동일 높이에 배치 |

> [MEMO] gap 값은 매치 카드 실제 높이(약 64px)에 따라 구현 시 조정 필요. 정확한 값은 `TournamentBracket.tsx` 구현 시 계산.

**4강 이하 토너먼트 처리:**

| tournament_size | 첫 라운드 | 열 구성 |
|----------------|-----------|---------|
| 4 | semifinal | 4강 → 결승 (+ 3/4위전) |
| 8 | quarterfinal | 8강 → 4강 → 결승 (+ 3/4위전) |
| 16 | round_of_16 | 16강 → 8강 → 4강 → 결승 (+ 3/4위전) |

> 브래킷은 항상 존재하는 라운드 열만 렌더링. 없는 라운드는 열 생략.

### 6-1. 일반 유저 — 결과 확인

```

    │     │     └── TournamentBracket
    │     └── [조별 순위] 탭 (클릭 시 전환)
    │           └── StandingsTable
    └── tournament.status === 'open' or 'draft' → "결과는 대회 종료 후 공개됩니다." 메시지
```

### 6-2. Organizer — 결과 미리보기 (`open` 상태)

```
/admin/tournaments/[id] (관리자 대시보드)
  → 별도 링크 또는 브라우저 직접 접근
  → /tournament/[id]/result
    → getUserWithRole() → role === 'organizer' → 항상 접근 허용
    → 동일 UI 렌더링 (미리보기 목적)
```

### 6-3. 탭 전환 인터랙션

```
초기 상태: activeTab = "bracket"
  → [대진표] 탭 클릭: activeTab = "bracket" (이미 선택됨, 변경 없음)
  → [조별 순위] 탭 클릭: activeTab = "standings"
      → TournamentBracket 숨김 (className="hidden")
      → StandingsTable 섹션 표시
  → [대진표] 탭 재클릭: activeTab = "bracket"
      → StandingsTable 섹션 숨김
      → TournamentBracket 표시
```

> 탭 전환은 `display: none / block` (hidden/block 클래스) 방식.  
> 데이터는 이미 서버에서 모두 fetch되어 props로 전달됨 → 탭 전환 시 추가 서버 요청 없음.

### 6-4. 에러 처리 플로우

```
데이터 fetch 실패 (API 에러)
  → page.tsx 서버 컴포넌트에서 error 감지
  → <p className="text-sm text-red-600">{에러 메시지}</p> 렌더링

```

## 8. 구현 시 주의사항

### 기존 컴포넌트 변경 시 영향 범위

- `lib/api/standings.ts`에서 `StandingRow` export 추가:  
  → 해당 타입은 현재 `getStandingsByGroup` 반환 타입에만 사용. export 추가는 breaking change 아님.

- `DragScroll` 컴포넌트 재사용:  
  → 현재 schedule 페이지에서 사용 중. props 변경 없이 그대로 사용 가능.

### 반응형 처리 우선순위

1. **브래킷 수평 스크롤** (최우선): `DragScroll` + `overflow-x-auto`로 모바일에서 좌우 스크롤 가능해야 함
2. **순위표 컬럼 숨김** (중요): `hidden sm:table-cell`로 보조 컬럼을 모바일에서 숨김
3. **탭 터치 영역** (중요): 탭 버튼 최소 `py-2 px-3` → 실제 터치 영역 44px 이상 확보
4. **챔피언 배너 단일 열** (보통): 복수 디비전 챔피언 카드 grid를 모바일에서 1열로

### 접근성 고려사항

- 탭 버튼: `role="tab"`, `aria-selected`, `aria-controls` 추가 권장
- 브래킷 매치 카드: 승자 표시에 색상만 사용하지 않고 텍스트로도 표시 (`font-semibold` + 텍스트 자체)
- 순위 강조: 배경색 외에 순위 이모지(🥇🥈🥉)로 색맹 사용자 대응

### 브래킷 연결선 구현 주의

- 매치 카드 높이: `py-2` × 2행 + 카드 패딩 = 약 64px
- 수직 연결선 높이는 매치 카드 높이에 따라 동적으로 결정되어야 함
- `gap` 방식 대신 각 라운드 열을 `justify-around`로 정렬하고, 연결선을 별도 div로 처리하는 방식 고려
- 구현이 복잡해질 경우 연결선 없이 화살표(→) 아이콘으로 대체 가능 [MEMO]

### 데이터 준비 (page.tsx에서 처리)

```typescript
// 1. 브래킷 데이터를 divisionId로 분류
const bracketByDivision = new Map<string, TournamentBracketMatchRow[]>();
bracketMatches.forEach((match) => {
  const arr = bracketByDivision.get(match.division_id) ?? [];
  arr.push(match);
  bracketByDivision.set(match.division_id, arr);
});

// 2. 순위 데이터를 league 그룹만 필터링
// getDivisionsWithGroups가 모든 그룹 타입을 반환하므로
// standings 데이터가 있는 그룹만 표시 (StandingsTable에서 empty 처리)
// 또는 page.tsx에서 group_id별 standings fetch 후 length > 0인 것만 전달

// 3. 챔피언 결정
const finalByDivision = new Map<string, TournamentBracketMatchRow>();
bracketMatches
  .filter((m) => m.group?.name === "final" && m.status === "completed")
  .forEach((m) => finalByDivision.set(m.division_id, m));
```

# 대회 장소 지도 연동 리서치

- **날짜**: 2026-05-15
- **기능명**: TournamentLocationMap
- **요구사항 요약**: Kakao Local API를 활용해 관리자가 대회 장소 입력 시 주소 자동완성을 제공하고, 선택된 주소의 위도/경도를 DB에 저장한다. 공개 대회 페이지에서는 "카카오맵으로 보기"와 "네이버 지도로 보기" 두 가지 외부 링크를 동시에 노출한다.

---

## 1. 기술 스택 요약

| 구분 | 내용 |
|------|------|
| **프레임워크** | Next.js 16.1.6 (App Router, React 19) |
| **언어** | TypeScript 5 |
| **스타일링** | Tailwind CSS v4 |
| **백엔드/DB** | Supabase (PostgreSQL) + Row Level Security |
| **인증** | Supabase Auth (이메일, Google OAuth, Kakao OAuth) |
| **상태 관리** | React 내장 (`useState`, `useTransition`, `useRef`, `useEffect`) — 별도 전역 상태 관리 라이브러리 없음 |
| **서버 액션** | Next.js Server Actions (`"use server"`) |
| **외부 라이브러리** | `lucide-react` (아이콘), `react-day-picker` (달력), `@dnd-kit/*` (드래그&드롭), `xlsx` (엑셀) |
| **패키지 매니저** | pnpm (node_modules/.pnpm 구조 확인) |
| **배포** | Vercel |

**핵심 포인트**: 외부 API 호출 라이브러리가 전혀 없다. 기존 코드에서 외부 HTTP API를 클라이언트에서 직접 호출하는 패턴이 없으며, 모든 데이터는 Supabase를 통해 처리된다. Kakao Local API는 이 프로젝트에서 최초로 도입되는 외부 REST API 호출 패턴이다.

**환경변수 관리**: `.env.local`을 사용하며, `NEXT_PUBLIC_` 접두사가 붙은 변수는 클라이언트에 노출된다. 현재 등록된 `NEXT_PUBLIC_` 변수는 `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `NEXT_PUBLIC_SUPABASE_URL` 두 가지뿐이다. Kakao JavaScript 키는 `NEXT_PUBLIC_KAKAO_LOCAL_API_KEY` 형태로 추가해야 한다.

## 4. 재사용 가능한 패턴

### 4-1. 클릭 아웃 감지 패턴 (드롭다운 닫기)
`BasicInfoTab.tsx`와 `NewTournamentForm.tsx` 모두에서 DayPicker 달력 드롭다운에 동일한 패턴 사용:

```typescript
const dropdownRef = useRef<HTMLDivElement>(null);
const [dropdownOpen, setDropdownOpen] = useState(false);

useEffect(() => {
  if (!dropdownOpen) return;
  const handleClick = (e: MouseEvent) => {
    if (dropdownRef.current && !dropdownRef.current.contains(e.target as Node)) {
      setDropdownOpen(false);
    }
  };
  document.addEventListener("mousedown", handleClick);
  return () => document.removeEventListener("mousedown", handleClick);
}, [dropdownOpen]);
```
자동완성 드롭다운에 그대로 재사용 가능.

### 4-2. useTransition 패턴 (Server Action 호출)
```typescript
const [isPending, startTransition] = useTransition();

startTransition(async () => {
  const result = await someServerAction(input);
  if (!result.ok) {
    setError(result.error);
    return;
  }
  setSuccess("저장 완료");
});
```
모든 Server Action 호출에서 동일 패턴 사용.

### 4-3. ApiResult / ActionResult 패턴
- `ApiResult<T>`: `{ data: T | null; error: string | null }`
- `ActionResult`: `{ ok: true; message?: string } | { ok: false; error: string }`
모든 API 함수와 Server Action이 이 타입을 반환.

### 4-4. `ADD COLUMN IF NOT EXISTS` 마이그레이션 패턴
기존 컬럼 추가 마이그레이션들 (0202, 0203)이 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 패턴 사용:
```sql
ALTER TABLE public.tournaments
  ADD COLUMN IF NOT EXISTS schedule_start_at TIMESTAMPTZ NULL;
```
`location_lat`, `location_lng` 추가 시 동일 패턴 사용.

### 4-5. requireOrganizer guard 패턴
모든 관리자 전용 Server Action은 함수 최상단에서 권한 확인:
```typescript
const authResult = await requireOrganizer();
if (!authResult.ok) return authResult;
```

### 4-6. revalidatePath 패턴
Server Action 성공 후 캐시 무효화:
```typescript
revalidatePath(`/admin/tournaments/${tournamentId}/edit`);
revalidatePath(`/admin`);
```

### 4-7. 디바운스 구현 참조 패턴
현재 프로젝트에 debounce 유틸리티 함수는 없다. `useRef`로 timeout ID를 관리하는 방식으로 직접 구현해야 한다:
```typescript
const debounceRef = useRef<ReturnType<typeof setTimeout> | null>(null);

const handleInputChange = (value: string) => {
  setValue(value);
  if (debounceRef.current) clearTimeout(debounceRef.current);
  debounceRef.current = setTimeout(() => {
    // API 호출
  }, 300);
};
```

```sql
-- (선택사항) 좌표 유효 범위 제약
-- location_lat: -90 ~ 90, location_lng: -180 ~ 180
-- 한국 좌표 범위는 위도 33~38, 경도 124~132 이나 범용성을 위해 전체 범위 허용
```

**컬럼 타입 선택**: PostgreSQL의 `double precision`(8바이트 부동소수점)은 위도/경도 좌표 저장에 표준적으로 사용된다. Kakao Local API는 `x`(경도)와 `y`(위도)를 `string` 타입으로 반환하므로, 프론트엔드에서 `parseFloat()`으로 변환 후 저장한다.

**기존 데이터 영향**: `ADD COLUMN IF NOT EXISTS`이므로 기존 rows는 `NULL`로 채워진다. 기존 대회들은 좌표가 없어 공개 페이지에서 텍스트만 노출되며 backward compatible하다.

### 5-5. 권한 정책 (RLS)

**추가 RLS 정책 불필요.** 근거:
- `location_lat`, `location_lng`는 `tournaments` 테이블의 새 컬럼이다.
- `tournaments` 테이블의 기존 RLS 정책을 그대로 상속받는다:
  - SELECT: `status in ('open', 'closed', 'finished')` (공개) + organizer (자신의 draft 포함)
  - UPDATE: `is_organizer()` (organizer만 수정 가능)
  - INSERT: `is_organizer()` (organizer만 생성 가능)
- 좌표 컬럼에 별도 row-level 권한 분리 필요 없음.
- Kakao Local API 호출은 클라이언트에서 직접 이루어지므로 Supabase RLS와 무관.

**Kakao API Key 노출**: `NEXT_PUBLIC_KAKAO_LOCAL_API_KEY`는 클라이언트에 노출된다. Kakao API 정책상 JavaScript 앱 키는 브라우저에서 사용하도록 설계되어 있으나, Kakao 개발자 콘솔에서 허용 도메인을 설정하여 키 남용을 방지해야 한다.

## 7. 구현 시 주의사항

### 7-1. Kakao Local API 키 관리
- **키 종류**: Kakao Local API는 REST API 키 (서버용) 또는 JavaScript 앱 키 (클라이언트용) 모두 사용 가능. 브라우저에서 직접 호출하므로 **JavaScript 앱 키**를 사용해야 한다.
- **환경변수 이름**: `NEXT_PUBLIC_KAKAO_LOCAL_API_KEY`로 통일.
- **허용 도메인 설정**: Kakao 개발자 콘솔 > 앱 > 플랫폼 > Web에서 `localhost:3000`, 프로덕션 도메인 등록 필수.
- **요청 헤더**: `Authorization: KakaoAK {REST_API_KEY}` 또는 JavaScript 키의 경우 `Authorization: KakaoAK {JS_KEY}`.
  - 실제로 Kakao Local REST API는 REST API 키를 사용. JavaScript 앱 키는 Kakao Maps SDK용이다.
  - **중요**: Kakao Local API (키워드 검색)는 REST API이므로 **REST API 키**를 사용해야 하나, 이는 서버 측 비밀 키다. 클라이언트에서 직접 노출하면 보안 문제가 생길 수 있음.
  - **권장 대안**: Next.js API Route (`/api/kakao-search`) 또는 Supabase Edge Function을 프록시로 사용하여 REST API 키를 서버에서만 보관하고, 클라이언트는 내부 엔드포인트를 호출하는 방식.
  - **간소화 대안**: Kakao Local API의 JavaScript 앱 키는 브라우저 CORS 허용 도메인 제한이 있으므로, Kakao 정책을 확인하여 허용 시 클라이언트 직접 호출 가능.

### 7-2. Kakao Local API 엔드포인트
- **키워드 검색**: `https://dapi.kakao.com/v2/local/search/keyword.json`
  - 파라미터: `query` (검색어), `size` (결과 수, 기본 15, 최대 15)
  - 응답: `documents[].place_name`, `documents[].address_name`, `documents[].road_address_name`, `documents[].x` (경도), `documents[].y` (위도)
- **좌표계**: Kakao API의 `x`는 경도(longitude), `y`는 위도(latitude). DB 컬럼명과 혼동 주의.
  - `location_lat = parseFloat(y)` (위도)
  - `location_lng = parseFloat(x)` (경도)

### 7-3. 지도 링크 형식

**카카오맵 링크** (좌표 필요):
```
https://map.kakao.com/link/map/{장소명},{lat},{lng}
```
예: `https://map.kakao.com/link/map/서울체육관,37.5665,126.9780`

장소명에 한글, 공백, 특수문자 포함 가능하므로 `encodeURIComponent()` 필요:
```typescript
const kakaoMapUrl = `https://map.kakao.com/link/map/${encodeURIComponent(tournament.location ?? tournament.name)},${tournament.location_lat},${tournament.location_lng}`;
```

**네이버 지도 링크** (텍스트 검색, 좌표 불필요):
```
https://map.naver.com/v5/search/{주소텍스트}
```
예: `https://map.naver.com/v5/search/서울 체육관`

`location` 텍스트만 있으면 좌표 없이도 링크 생성 가능:
```typescript
const naverMapUrl = `https://map.naver.com/v5/search/${encodeURIComponent(tournament.location ?? '')}`;
```

**노출 조건 요약**:
```typescript
const hasCoords = location_lat !== null && location_lng !== null;
const hasLocation = !!location;

// 카카오맵: 좌표 있을 때만
{hasCoords && <a href={kakaoMapUrl}>카카오맵으로 보기</a>}

// 네이버 지도: 텍스트 주소만 있으면 항상 (기존 대회 포함)
{hasLocation && <a href={naverMapUrl}>네이버 지도로 보기</a>}
```

**네이버 지도 링크의 강점**: 좌표 없이 주소 텍스트만으로 동작하므로 기존에 저장된 모든 대회에서 즉시 표시 가능. 새 마이그레이션 적용 전 기존 레코드에도 효과 있음.

### 7-4. 자동완성 선택 후 직접 편집 시 좌표 초기화
요구사항: "자동완성 선택 전 직접 편집하면 좌표는 초기화(null)된다"

구현 포인트:
```typescript
const handleLocationChange = (text: string) => {
  setLocation(text);
  // 직접 입력 시 좌표 초기화
  setLocationLat(null);
  setLocationLng(null);
};

const handlePlaceSelect = (place: KakaoLocalPlace) => {
  setLocation(place.place_name);
  setLocationLat(parseFloat(place.y)); // y = 위도
  setLocationLng(parseFloat(place.x)); // x = 경도
  setDropdownOpen(false);
};
```

### 7-5. 기존 데이터 호환성
- 기존 대회들은 `location_lat`, `location_lng`가 `NULL`이다.
- `TournamentStickyPanel`에서 분기 처리:
  ```typescript
  const hasCoords = tournament.location_lat !== null && tournament.location_lng !== null;
  ```
- `hasCoords`가 `false`이면 기존과 동일하게 텍스트만 표시.

### 7-6. 타입 import 체인 수정
`TournamentEditRow`와 `PublicTournamentRow`에 좌표 필드가 추가되면, 이 타입을 사용하는 모든 컴포넌트에 자동으로 새 필드가 노출된다:
- `BasicInfoTab.tsx`: `tournament: TournamentEditRow` prop에서 좌표 초기값 읽기 가능
- `TournamentStickyPanel.tsx`: `tournament: PublicTournamentRow` prop에서 좌표 읽기 가능
- `TournamentCard.tsx`: `tournament: TournamentListItem` prop (별도 수정 시)

### 7-7. 디바운스 구현
300ms 디바운스를 `useRef`로 직접 구현. `useEffect` cleanup에서 반드시 `clearTimeout` 호출:
```typescript
const debounceRef = useRef<ReturnType<typeof setTimeout> | null>(null);

useEffect(() => {
  return () => {
    if (debounceRef.current) clearTimeout(debounceRef.current);
  };
}, []);
```

### 7-8. 충돌 가능성
- `BasicInfoTab.tsx`의 수정이 크기 때문에, 동시에 다른 탭이나 form을 수정하는 작업과 충돌 위험이 있다. 이 기능 구현 중에는 BasicInfoTab 관련 작업을 분리해서 진행.
- `lib/api/tournaments.ts`는 프로젝트 전체에서 가장 많이 import되는 파일이므로 타입 변경 시 TypeScript 컴파일 에러가 다수 발생할 수 있다. 타입 확장은 backward compatible하게(기존 필드 유지, 신규 필드 추가만).

### 7-9. 네이버 지도 API 고려사항

**네이버 Local Search API** (주소 자동완성 용도 - 이번 Phase에서는 미사용):
- 엔드포인트: `https://openapi.naver.com/v1/search/local.json`
- 인증: `X-Naver-Client-Id`, `X-Naver-Client-Secret` 헤더
- 응답 좌표계: **KATECH (Korea TM128)** → WGS84 변환 필요 (복잡)
- 이번 Phase에서는 자동완성을 Kakao로 통일하고, 네이버는 링크 노출만 담당

**네이버 지도 링크 방식**: `https://map.naver.com/v5/search/{query}` 는 별도 API 키 불필요. 순수 URL 조합이므로 환경변수 추가나 서버 액션 변경 없이 TournamentStickyPanel 프론트엔드 변경만으로 구현 완료.

**네이버 지도 모바일 딥링크** (이번 범위 제외):
```
naver://map?lng={lng}&lat={lat}  (모바일 앱)
```

### 7-10. Next.js API Route vs 클라이언트 직접 호출
Kakao Local REST API를 클라이언트에서 직접 호출 시 CORS 문제가 발생할 수 있다 (Kakao 서버가 브라우저 직접 요청을 허용하는지 확인 필요). 안전한 방법:

**Option A (권장)**: Next.js API Route 프록시
```
클라이언트 → GET /api/kakao-place-search?q=검색어 → Next.js Route Handler → Kakao REST API
```
- REST API 키를 서버에서만 보관 (`KAKAO_LOCAL_REST_API_KEY`, `NEXT_PUBLIC_` 없음)
- CORS 문제 없음

**Option B (간단)**: 클라이언트 직접 호출
```
클라이언트 → Kakao Local API (dapi.kakao.com)
```
- `NEXT_PUBLIC_KAKAO_LOCAL_API_KEY` (REST API 키가 클라이언트에 노출)
- Kakao API가 CORS를 허용하면 동작함 (허용하는 것으로 알려져 있으나 공식 문서 확인 필요)

### 7-11. 후속 확장 포인트 (Phase 2, 3)
- **Phase 2 - 지도 iframe 임베드**: `location_lat`, `location_lng`가 이미 저장되어 있으므로, Kakao Maps SDK를 추가하고 `TournamentStickyPanel`에 지도 컴포넌트를 삽입하면 된다.
- **Phase 3 - 코트별 위치**: `courts` 테이블에 `court_lat`, `court_lng` 컬럼 추가. 현재 `courts` 테이블은 `id`, `tournament_id`, `name`, `display_order`만 있음 (`supabase/migrations/0041_court_management.sql` 참조).

## 9. 결론

이번 기능은 **DB 컬럼 2개 추가 + 타입 확장 + 자동완성 UI 컴포넌트 신규 구현 + 기존 2개 컴포넌트 수정**으로 구성된 비교적 독립적인 기능이다. 네이버 지도 링크는 별도 API 키 없이 URL 조합만으로 구현되므로 추가 복잡도가 낮다.

**핵심 의사결정 사항**:
1. **Kakao API 호출 방식**: REST API 키 보안을 위해 Next.js API Route 프록시 방식(Option A)을 권장하나, 개발 속도를 위해 클라이언트 직접 호출(Option B)도 가능. 클라이언트 직접 호출 시 Kakao API의 CORS 허용 여부와 REST API 키 노출 보안을 팀과 협의해서 결정.
2. **자동완성 컴포넌트 재사용 범위**: BasicInfoTab(편집)과 NewTournamentForm(신규 생성) 양쪽에서 재사용할 수 있도록 `components/location/` 하위에 독립 컴포넌트로 분리 권장.
3. **TournamentCard 수정 여부**: 요구사항이 공개 대회 페이지(상세 페이지)만 명시했으므로 목록 카드(TournamentCard)는 이번 범위에서 제외해도 됨.
4. **네이버 vs 카카오 자동완성**: 이번 Phase는 Kakao 단일 자동완성으로 통일. 네이버 Local Search API는 KATECH 좌표계 변환 복잡도가 있어 Phase 후속에서 검토.

**위험 요소**:
- `lib/api/tournaments.ts`는 가장 많이 import되는 파일이므로 타입 변경 시 TypeScript 컴파일 에러가 다수 발생할 수 있음. 단, 기존 필드를 삭제하지 않고 신규 필드만 추가하므로 breaking change 없음.
- Kakao Local API의 CORS 정책 및 REST API 키 노출 보안 확인 필요.

**네이버 지도 링크의 즉시 적용 범위**: 네이버 지도 링크는 `location` 텍스트만 있으면 되므로 DB 마이그레이션과 무관하게 TournamentStickyPanel 수정만으로 기존 모든 대회에 즉시 적용됨. 선구현 가능.

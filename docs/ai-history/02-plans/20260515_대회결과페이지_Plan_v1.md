### Phase 2. 타입 정의

**파일: `lib/api/standings.ts`**

**변경 1 — `StandingRow` export 추가**

현재 `StandingRow`는 module-local 타입. `StandingsTable.tsx`에서 import하려면 export 필요.

```
// 의사코드
// 현재: type StandingRow = { ... }
// 변경: export type StandingRow = { ... }
// 영향: 기존 사용처 없음 (module-local이었으므로 breaking change 아님)
```

**변경 2 — `DivisionGroupRow` 타입에 groups.type 추가**

현재 `getDivisionsWithGroups`의 groups select가 `"id,name,order"` 만 조회.  
`type` 컬럼을 추가해야 page.tsx에서 league 그룹 필터링 가능.

```
// 의사코드
// 기존 DivisionGroupRow:
//   groups: { id: string; name: string; order: number }[] | null
//
// 변경 후 DivisionGroupRow:
//   groups: { id: string; name: string; order: number; type: string }[] | null
//
// getDivisionsWithGroups 쿼리:
//   .select("id,name,groups(id,name,order)")   ← 기존
//   .select("id,name,groups(id,name,order,type)")  ← 변경
```

**파일: `app/(app)/tournament/[id]/result/page.tsx` 내 로컬 타입**

```typescript
// page.tsx 내 로컬 타입 선언 (import 불필요)

type BracketSection = {
  divisionId: string;
  divisionName: string;
  matches: TournamentBracketMatchRow[];
};

type StandingSection = {
  divisionId: string;
  divisionName: string;
  groupId: string;
  groupName: string;
  groupOrder: number;
  standings: StandingRow[];
};

type ChampionEntry = {
  divisionName: string | null;  // null이면 단일 디비전
  teamName: string | null;      // null이면 결승 미완료
};
```

**Import 경로 정리:**
- `TournamentBracketMatchRow` — `@/lib/api/matches`
- `StandingRow` — `@/lib/api/standings` (Phase 2에서 export 추가 후)

**파일: `app/(app)/tournament/[id]/result/page.tsx` — 데이터 준비 로직**

`ResultContent` 서버 컴포넌트 내 데이터 fetch 및 변환 의사코드:

```
// Step 1: 병렬 fetch
[tournamentResult, bracketResult, divisionsResult, userResult]
  = await Promise.all([
    getPublicTournamentById(tournamentId),
    getTournamentBracketMatches(tournamentId),
    getDivisionsWithGroups(tournamentId),   ← 이제 type 포함
    getUserWithRole(),
  ])

// Step 2: 에러/접근 제어 early return
if (에러 or 존재하지 않는 대회) → 에러 메시지 return
isOrganizer = userResult.role === 'organizer'
isPublicVisible = tournament.status in ['closed', 'finished']
if (!isOrganizer && !isPublicVisible) → "결과는 대회 종료 후 공개됩니다." return

// Step 3: 브래킷 데이터를 divisionId별 분류 (버그 수정)
bracketByDivision = new Map<string, TournamentBracketMatchRow[]>()
bracketMatches.forEach(match => {
  const arr = bracketByDivision.get(match.division_id) ?? []
  arr.push(match)
  bracketByDivision.set(match.division_id, arr)
})

// Step 4: 챔피언 결정 (divisionId별)
championByDivision = new Map<string, string | null>()
bracketMatches
  .filter(m => m.group?.name === 'final' && m.status === 'completed')
  .forEach(m => {
    const teamName = m.winner_team_id === m.team_a?.id
      ? m.team_a?.team_name
      : m.team_b?.team_name
    championByDivision.set(m.division_id, teamName ?? null)
  })

champions: ChampionEntry[] = divisions.map(div => ({
  divisionName: divisions.length > 1 ? div.name : null,
  teamName: championByDivision.get(div.id) ?? null,
}))

// Step 5: BracketSection 조립
bracketSections: BracketSection[] = divisions
  .filter(div => bracketByDivision.has(div.id))
  .map(div => ({
    divisionId: div.id,
    divisionName: div.name,
    matches: bracketByDivision.get(div.id) ?? [],
  }))

// Step 6: StandingSection 조립 (league 그룹만)
// 각 디비전의 groups 중 type === 'league'인 것만 처리
standingResults = await Promise.all(
  divisions.flatMap(div =>
    (div.groups ?? [])
      .filter(g => g.type === 'league')  ← 핵심: league 그룹만 필터링
      .map(async g => {
        const result = await getStandingsByGroup(g.id)
        return {
          divisionId: div.id,
          divisionName: div.name,
          groupId: g.id,
          groupName: g.name,
          groupOrder: g.order,
          standings: result.data ?? [],
          error: result.error,
        }
      })
  )
)

// 에러 처리
standingsError = standingResults.find(r => r.error)
if (standingsError) → 에러 메시지 return

standingSections: StandingSection[] = standingResults
  .filter(r => r.standings.length > 0)  ← 데이터 없는 그룹 제외
  .sort((a, b) => {
    if (a.divisionName !== b.divisionName)
      return a.divisionName.localeCompare(b.divisionName)
    return a.groupOrder - b.groupOrder
  })

// Step 7: 렌더링
return (
  <main>
    ← 뒤로 가기 링크
    <Card> 대회 헤더 </Card>
    <ChampionBanner champions={champions} hasMultipleDivisions={divisions.length > 1} />
    <ResultTabs
      bracketSections={bracketSections}
      standingSections={standingSections}
      hasMultipleDivisions={divisions.length > 1}
    />
  </main>
)
```

**핵심 구현 로직:**

```
// Props: { matches: TournamentBracketMatchRow[] }

// Step 1: 라운드별 분류
const roundOrder = ["round_of_16", "quarterfinal", "semifinal", "third_place", "final"]
roundMap = new Map<string, TournamentBracketMatchRow[]>()
matches.forEach(m => {
  const round = m.group?.name ?? ""
  if (!round) return
  roundMap.get(round)?.push(m) ?? roundMap.set(round, [m])
})

// Step 2: 라운드 정렬 (roundOrder 기준)
sortedRounds = roundOrder.filter(r => roundMap.has(r))
// third_place는 final 바로 앞에 있는 것이 맞음

// Step 3: initialRound 결정 (seed 기반 정렬을 위해)

initialRound = getInitialRoundFromRoundMap(roundMap)

// Step 4: 라운드 내 경기 정렬
// compareTournamentMatchOrder(left, right, initialRound) 사용

// → initialRound에서는 seed 기준, 다른 라운드는 created_at 기준
sortedMatchesPerRound = 각 라운드별 .sort((a,b) => compareTournamentMatchOrder(a, b, initialRound))

// Step 5: 렌더링

        .filter(r => r !== "third_place" && r !== "final")
        .map(round => (

        {roundMap.has("third_place") && (

        )}
        {roundMap.has("final") && (
```

## 6. 리스크 및 주의사항

### 6-1. getDivisionsWithGroups 변경 영향 범위

`lib/api/standings.ts`의 `getDivisionsWithGroups`를 수정 시, 이 함수를 호출하는 모든 파일 확인 필요.

현재 호출 파일:
- `app/(app)/tournament/[id]/result/page.tsx` — 이번에 수정 대상
- `lib/api/standings.ts` 자체 (re-export 용도)

`type` 컬럼 추가는 **additive 변경**이므로 기존 코드가 `type` 필드를 무시해도 동작에 영향 없음.  
단, TypeScript 컴파일 에러가 없는지 수정 후 확인 필요.

### 6-2. TournamentBracket 브래킷 연결선 gap 값

UI 스펙에서 제안한 gap 값(`gap-2`, `gap-10`, `gap-28`)은 매치 카드의 실제 렌더링 높이에 의존.  
`BracketMatchCard` 높이는 `py-2` × 2행 + border = 약 72px로 예상되나, 실제 값이 다를 수 있음.

**위험**: 연결선이 정확한 중간 지점에 맞지 않을 경우 브래킷이 어색하게 보임.

**대응 방안**:
1. 구현 후 실제 카드 높이를 측정해 gap 값 조정
2. 연결선 높이를 JavaScript로 동적 계산 (`useRef` + `getBoundingClientRect`) — 복잡도 증가
3. 연결선 없이 화살표(`→`) 아이콘으로 대체 — 가장 단순하지만 시각적으로 덜 세련됨

**권장**: 옵션 1로 시작하고, 시각적으로 문제가 있으면 옵션 3으로 폴백.

### 6-3. league 그룹 타입 필터링 의존성

`getDivisionsWithGroups` 수정 전에 page.tsx를 작성하면 `g.type`이 undefined가 됨.  
반드시 Step 1(standings.ts 수정)이 Step 6(page.tsx 수정) 전에 완료되어야 함.

### 6-4. 복수 디비전 챔피언 배너 — 미확정 케이스

챔피언 배너에서 `isOrganizer`를 prop으로 받아야 하는데, `ChampionBanner`는 서버 컴포넌트이므로 problem 없음.  
`getUserWithRole()` 결과를 page.tsx에서 `isOrganizer` boolean으로 변환해 prop으로 전달.

일반 유저가 `open` 상태 대회에 접근 시 이미 page.tsx에서 early return 처리되므로 ChampionBanner까지 도달하지 않음.  
`isOrganizer=true`인 경우에만 미확정 배너가 표시되는 경우는: organizer가 `open/closed` 상태에서 미리 보는 경우.

### 6-5. `compareTournamentMatchOrder` 사용 시 initialRound 필요

`compareTournamentMatchOrder(left, right, initialRound)` 함수는 `initialRound`가 필요.  
이 값을 `getInitialRoundFromRoundMap(roundMap)`으로 구한다.  
`getInitialRoundFromRoundMap`은 내부적으로 `getInitialTournamentRound`를 호출 (lib/formatters/matchLabel.ts).

`TournamentBracket.tsx`가 클라이언트 컴포넌트이므로 이 유틸 함수들을 import해야 함.  
`lib/formatters/tournamentMatchOrder.ts`는 서버/클라이언트 무관한 순수 함수이므로 클라이언트에서 import 가능.

### 6-6. `StandingRow` 타입 충돌 가능성

`lib/api/standings.ts`에서 `StandingRow`를 export하면, 혹시 다른 파일에서 동일 이름의 타입을 local로 선언하고 있을 경우 충돌 가능.  
`grep -r "StandingRow" --include="*.ts" --include="*.tsx"` 로 사전 확인 권장.

### 6-7. `TournamentBracketMatchRow`의 `created_at` 정렬 정확성

`compareTournamentMatchOrder`의 비초기 라운드 정렬 기준은 `created_at`.  
토너먼트 매치의 `created_at`은 브래킷 생성 시 DB에 삽입된 시간.  
같은 대회, 같은 라운드의 매치들이 동시에 삽입되면 `created_at`이 동일할 수 있음 → `id` 기준으로 폴백됨 (함수 내부 처리).  
시각적 순서가 어긋날 가능성 낮지만, 실제 데이터로 검증 필요.

### 핵심 버그 수정 포인트

1. **division_id 분리 누락**: `getTournamentBracketMatches` 반환값을 `division_id`로 먼저 그룹화하지 않으면 복수 디비전 대회에서 모든 경기가 혼합 표시됨. Phase 3 Step 3에서 수정.

2. **league/tournament 그룹 미구분**: `getDivisionsWithGroups`가 모든 그룹 타입을 반환하므로, `type === 'league'` 필터 없이 순위를 조회하면 tournament 그룹에 대한 빈 쿼리가 발생. Phase 2 + Phase 3에서 수정.

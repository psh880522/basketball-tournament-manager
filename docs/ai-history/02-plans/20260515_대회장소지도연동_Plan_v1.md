## 3. Phase별 구현 계획

### Phase 1. DB 스키마 / 마이그레이션

**파일**: `supabase/migrations/0256_tournaments_location_coords.sql`

#### 신규 컬럼

| 컬럼 | 타입 | 제약 | 설명 |
|------|------|------|------|
| `location_lat` | `double precision` | NULL 허용 | 위도 (WGS84, Kakao `y` 값) |
| `location_lng` | `double precision` | NULL 허용 | 경도 (WGS84, Kakao `x` 값) |

#### 의사코드

```
ALTER TABLE public.tournaments
  ADD COLUMN IF NOT EXISTS location_lat double precision NULL,
  ADD COLUMN IF NOT EXISTS location_lng double precision NULL;
```

- `ADD COLUMN IF NOT EXISTS` 패턴 사용 (0202, 0203 마이그레이션과 동일한 패턴)
- 기존 rows는 NULL로 채워짐 → 하위 호환성 보장

#### 롤백 방법

```
ALTER TABLE public.tournaments
  DROP COLUMN IF EXISTS location_lat,
  DROP COLUMN IF EXISTS location_lng;
```

#### 인덱스

- 별도 인덱스 불필요: 좌표 기반 공간 쿼리(PostGIS)는 이번 Phase 범위 외

#### RLS

- 추가 RLS 정책 불필요: `tournaments` 테이블 기존 RLS 정책 자동 상속
  - SELECT: `status in ('open','closed','finished')` 또는 organizer 본인
  - UPDATE: `is_organizer()` (organizer/manager만 수정 가능)

### Phase 3. 서버 액션 / API

#### 3-1. 신규 파일: `app/api/kakao-place-search/route.ts`

Next.js Route Handler (GET) — Kakao Local API 프록시

**역할**: REST API 키를 서버에서만 보관하고 클라이언트는 내부 엔드포인트 호출

**의사코드**:
```
GET /api/kakao-place-search?q={query}

1. query 파라미터 검증
   - 없거나 2글자 미만이면 400 반환

2. process.env.KAKAO_LOCAL_REST_API_KEY 참조
   - 없으면 500 반환

3. fetch("https://dapi.kakao.com/v2/local/search/keyword.json", {
     headers: { Authorization: `KakaoAK ${KAKAO_LOCAL_REST_API_KEY}` },
     query: { query: q, size: 5 }
   })

4. Kakao 응답 그대로 JSON으로 전달
   - 성공: { documents: KakaoLocalPlace[], meta: {...} }
   - Kakao 에러: 상태코드 포함 에러 응답 전달
```

**환경변수**: `.env.local`에 `KAKAO_LOCAL_REST_API_KEY=...` 추가 필요 (Vercel 배포 시 환경변수 등록)

### Phase 4. 프론트엔드

#### 4-1. 신규 파일: `components/location/LocationAutocomplete.tsx`

`"use client"` 클라이언트 컴포넌트

**Props**:
```
interface LocationAutocompleteProps {
  value: string
  onChange: (text: string) => void      // 직접 입력 시 호출 → 좌표 초기화 트리거
  onSelect: (place: KakaoLocalPlace) => void  // 자동완성 선택 시 호출
  hasCoords?: boolean                   // 힌트 텍스트 표시 제어
  placeholder?: string
  disabled?: boolean
}
```

**내부 상태**:
```
suggestions: KakaoLocalPlace[]   // 검색 결과 목록
isOpen: boolean                  // 드롭다운 열림 여부
isLoading: boolean               // API 호출 중
apiError: string | null          // API 에러 메시지
```

**핵심 로직 의사코드**:
```
[디바운스 검색]
debounceRef = useRef<timeout | null>(null)

handleInputChange(text):
  onChange(text)  // 부모에 알려서 좌표 초기화
  clearTimeout(debounceRef.current)
  if text.length < 2:
    setSuggestions([])
    setIsOpen(false)
    return
  debounceRef.current = setTimeout(async () => {
    setIsLoading(true)
    setApiError(null)
    try:
      res = await fetch(`/api/kakao-place-search?q=${encodeURIComponent(text)}`)
      data = await res.json()
      setSuggestions(data.documents ?? [])
      setIsOpen(true)
    catch:
      setApiError("검색에 실패했습니다. 직접 입력해 주세요.")
      setIsOpen(true)
    finally:
      setIsLoading(false)
  }, 300)

[아이템 선택]
handleSelect(place: KakaoLocalPlace):
  onSelect(place)
  setIsOpen(false)
  setSuggestions([])

[클릭 아웃 감지] — BasicInfoTab DayPicker 패턴 재사용
containerRef = useRef<HTMLDivElement>(null)
useEffect:
  if !isOpen: return
  handleClick = (e) => if !containerRef.current.contains(e.target): setIsOpen(false)
  document.addEventListener("mousedown", handleClick)
  return cleanup

[키보드 접근성]
onKeyDown:
  ArrowDown → focusedIndex++
  ArrowUp   → focusedIndex--
  Enter     → handleSelect(suggestions[focusedIndex])
  Escape    → setIsOpen(false)
  Tab       → setIsOpen(false)

[클린업]
useEffect cleanup: clearTimeout(debounceRef.current)
```

**렌더링 구조**:
```
<div className="relative" ref={containerRef}>
  <input
    className="w-full rounded-md border border-gray-300 px-3 py-2 text-sm focus:outline-none"
    value={value}
    onChange={(e) => handleInputChange(e.target.value)}
    placeholder={placeholder}
    disabled={disabled}
    aria-autocomplete="list"
    aria-expanded={isOpen}
  />
  
  {isOpen && (
    <div className="absolute left-0 top-full z-50 mt-1 w-full rounded-md border border-gray-200 bg-white shadow-lg max-h-60 overflow-y-auto"
         role="listbox">
      {isLoading → <p className="px-3 py-2 text-xs text-slate-400">검색 중...</p>}
      {apiError → <p className="px-3 py-2 text-xs text-slate-400">{apiError}</p>}
      {!isLoading && !apiError && suggestions.length === 0
        → <p className="px-3 py-2 text-xs text-slate-400">검색 결과가 없습니다.</p>}
      {suggestions.map(place →
        <div role="option" onClick={() => handleSelect(place)}
             className="cursor-pointer px-3 py-2 hover:bg-slate-50">
          <p className="text-sm font-medium text-slate-800">{place.place_name}</p>
          <p className="text-xs text-slate-400">{place.road_address_name || place.address_name}</p>
        </div>
      )}
    </div>
  )}
  
  {/* 힌트 텍스트 */}
  {value && (
    hasCoords
      ? <p className="mt-1 text-xs text-emerald-600">✓ 위치가 선택되었습니다</p>
      : <p className="mt-1 text-xs text-slate-400">목록에서 선택하면 지도 링크가 생성됩니다</p>
  )}
</div>
```

### Phase 5. 권한 정책 (RLS)

**추가 RLS 정책 없음.**

- `location_lat`, `location_lng`는 `tournaments` 테이블의 컬럼으로, 기존 RLS 정책 자동 상속
  - 공개 조회: `status in ('open', 'closed', 'finished')` — 모든 사용자 조회 가능
  - 수정: `is_organizer()` — organizer/manager만 가능
  - 신규 생성: `is_organizer()` — organizer/manager만 가능
- Kakao Local API 호출은 서버 Route Handler에서 처리 → Supabase RLS와 무관

## 6. 리스크 및 주의사항

### 6-1. Kakao x/y 좌표 혼동 주의

**위험**: Kakao Local API는 `x`가 경도(longitude), `y`가 위도(latitude)다. 일반적인 (lat, lng) 순서와 반대.

**대응**:
```
location_lat = parseFloat(place.y)   // y = 위도 (latitude)
location_lng = parseFloat(place.x)   // x = 경도 (longitude)
```
- `LocationAutocomplete.tsx`의 `onSelect` 콜백과 `BasicInfoTab`, `NewTournamentForm` 모두 동일 규칙 적용
- 카카오맵 링크 URL: `{lat},{lng}` 순서로 전달 — DB 값 그대로 사용 가능

### 6-2. lib/api/tournaments.ts 타입 변경 영향

**위험**: 이 파일은 프로젝트 전체에서 가장 많이 import되므로 타입 변경 시 TypeScript 컴파일 에러가 다수 발생할 수 있음.

**대응**: 기존 필드를 삭제하지 않고 신규 필드만 추가 (`location_lat?: number | null` 방식은 사용하지 않고 `location_lat: number | null`로 명시). 기존 코드에서 이 필드를 참조하지 않으면 추가만으로 breaking change 없음.

### 6-3. Kakao REST API 키 노출 방지

**위험**: `NEXT_PUBLIC_` 접두사 실수로 클라이언트에 노출될 경우 API 키 남용 가능.

**대응**:
- 환경변수명: `KAKAO_LOCAL_REST_API_KEY` (NEXT_PUBLIC_ 없음)
- 참조 위치: `app/api/kakao-place-search/route.ts` 서버 코드에서만 사용
- Kakao 개발자 콘솔 앱 설정에서 허용 도메인 등록: `localhost:3000`, 프로덕션 도메인

### 6-4. 기존 대회 데이터 하위 호환성

**위험**: 기존 대회들은 `location_lat`, `location_lng`가 NULL이므로 공개 페이지에서 카카오맵 링크가 표시되지 않을 수 있음.

**대응 (설계에 반영됨)**:
- `TournamentStickyPanel`: 카카오맵 링크는 좌표 있을 때만 표시, 네이버 지도 링크는 텍스트 있으면 표시
- 기존 대회는 네이버 지도 링크가 즉시 표시됨 (API 키 불필요, 텍스트 검색)
- 좌표를 추가하려면 관리자가 편집 페이지에서 자동완성으로 재선택 후 저장 필요

### 6-5. encodeURIComponent 누락 시 URL 오류

**위험**: 장소명에 한글, 공백, 특수문자 포함 시 지도 URL이 깨질 수 있음.

**대응**: `TournamentStickyPanel`에서 카카오맵/네이버 지도 URL 생성 시 반드시 `encodeURIComponent()` 적용

### 6-6. Kakao API 응답 지연 UX

**위험**: 디바운스 후 API 응답까지 공백 시간에 사용자 혼란 가능.

**대응**: `isLoading` 상태 시 드롭다운에 "검색 중..." 표시 → 응답 대기 중임을 명확히 안내

### 6-7. NewTournamentForm FormData 방식 주의

**위험**: `NewTournamentForm`은 FormData로 서버 액션을 호출하므로, 숫자 타입의 좌표를 string으로 직렬화 후 서버에서 `parseFloat()` 변환 필요.

**대응**:
```
클라이언트: formData.set("location_lat", form.locationLat?.toString() ?? "")
서버: const rawLat = formData.get("location_lat") as string
      const location_lat = rawLat ? parseFloat(rawLat) : null
```
- `NaN` 방어: `parseFloat` 결과가 `NaN`이면 `null`로 처리

## 7. 결론

이번 구현은 **신규 파일 4개 + 수정 파일 6개**로 구성된다. 핵심 의존 관계는 **타입 체인** (DB 컬럼 → TypeScript 타입 → 서버 액션 타입 → 컴포넌트 props)이며, 이 순서로 진행하면 TypeScript 컴파일 에러를 최소화할 수 있다.

**가장 중요한 구현 포인트**:
1. Kakao `x`=경도, `y`=위도 혼동 방지 — `location_lat = parseFloat(y)`
2. REST API 키를 `NEXT_PUBLIC_` 없이 서버 전용으로 보관
3. 기존 대회 하위 호환성 — 좌표 null 시 카카오맵 링크 숨김, 네이버 링크는 표시

**필수 구현 범위**: Phase 1~4 (DB + 타입 + API 프록시 + 자동완성 컴포넌트 + 편집 탭 + 공개 페이지 링크)  
**권장 구현 범위**: NewTournamentForm + createTournamentAction (신규 생성 시도 좌표 저장)
